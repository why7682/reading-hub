    218. The Skyline Problem 🔴 Hard#

    Tags: Array, Divide and Conquer, Binary Indexed Tree, Segment Tree, Sweep Line, Sorting, Heap (Priority Queue), Ordered Set

    Problem#

    给一组矩形 buildings[i] = [left, right, height]，输出其并集上视轮廓的"关键点"列表：每个点是某段水平线的左端点；末尾以 \((x_{\max}, 0)\) 标记结束。\(n \le 10^4\)，坐标范围 \(2^{31} - 1\)。

    背景#

    每个建筑是一个底边贴地的矩形。把它们叠在一起，从远处看，最上面的边界就是一条阶梯状的折线。我们要做的，是在每个横坐标 \(x\) 上回答一个问题：站在 \(x\) 处往上看，最高的建筑顶在哪里？

    把这个"最高顶"记成 \(x\) 的函数，就得到一条由水平段拼成的曲线。它只在某些位置"跳变"——而题目要的关键点，正是这些跳变的位置。整道题的难点，全在于如何高效地找出所有跳变点；下面先把这条曲线写成精确的式子，再从它的结构推出算法。

    形式化#

    设 \(\mathcal{B} = \{(l_i, r_i, h_i)\}\)，每个建筑占据横向半开区间 \([l_i, r_i)\)、高度 \(h_i\)。在横坐标 \(x\) 处，"覆盖 \(x\) 的所有建筑"是集合 \(\{h_i : l_i \le x < r_i\}\)；没有建筑时约定高度为 \(0\)。于是"最高顶"是

    \[H(x) = \max\Big(\{h_i : l_i \le x < r_i\} \cup \{0\}\Big).\]

    注意 \(0\) 放在 \(\max\) 的内部作为候选值：它保证空集时 \(H(x)=0\)，对应地面。半开区间 \([l_i, r_i)\) 的约定很关键——建筑在 \(x = r_i\) 处已经"不再覆盖"，所以右边界是退出而非进入。

    \(H(x)\) 是一个分段常值函数：在两个相邻的临界横坐标之间它取定值，只在临界处跳变。要输出的关键点，就是 \(H\) 的每个跳变点 \((x, H(x^+))\)，按 \(x\) 升序排列；这里 \(H(x^+)\) 是 \(x\) 右侧的取值——因为关键点标记的是某段水平线的左端点，记录的应是跳变之后、即将延续的那个高度。

    整页接下来的所有推导，都围绕一个问题展开：\(H(x)\) 在哪里跳变，跳到多少。

    想法#

    朴素尝试与它的破绽#

    最直接的想法：既然要的是 \(H\) 在各处的值，那就逐个 \(x\) 算 \(H(x)\)，发现值变了就记一个关键点。

    这立刻撞上两堵墙。第一，\(x\) 是连续的（坐标可达 \(2^{31}-1\)），无法"逐个"枚举。退一步，即便只在整数格点上扫，范围也有 \(2^{31}\) 个点，对每个点再遍历 \(n\) 个建筑判断覆盖，是 \(\Theta(2^{31} \cdot n)\)，完全不可行。第二，更根本地，这种盲扫做了大量无用功——\(H(x)\) 在绝大多数 \(x\) 上根本不变。

    破绽指向了出路。回到 \(H\) 的定义：它分段常值，只在临界处跳变。那么 \(H\) 究竟能在哪些 \(x\) 跳变？只有当"覆盖 \(x\) 的建筑集合"发生改变时，\(\max\) 才可能改变。而这个集合只在某个建筑进入（\(x = l_i\)）或退出（\(x = r_i\)）时才变化。于是：

    \(H(x)\) 的所有跳变点，都落在 \(\{l_i\} \cup \{r_i\}\) 这 \(2n\) 个横坐标里。

    无穷的连续定义域，被无损地压缩成了 \(2n\) 个候选位置。我们不必扫遍所有 \(x\)，只需在这 \(2n\) 个边界处检查 \(H\) 是否跳变。盲扫的两堵墙就此同时倒下：候选位置从 \(2^{31}\) 降到 \(2n\)，且每个候选都"可能有用"。

    在边界处求 \(H\)：先定不变量，再读出算法#

    现在把 \(2n\) 个边界按 \(x\) 升序处理。每到一个边界，我们要算的是当前的 \(H(x)\)，也就是 \(\max\big(\{h_i : l_i \le x < r_i\} \cup \{0\}\big)\)。直接重算这个集合是 \(O(n)\)，总体又退回 \(O(n^2)\)。要快，就得在扫描中增量维护这个集合。于是先把希望维护的性质写死成不变量，算法再从它读出来：

    不变量：处理完所有 \(x \le x_0\) 的边界后，多重集 \(A\) 恰好等于 \(\{h_i : l_i \le x_0 < r_i\} \cup \{0\}\)。

    这正是 \(H(x_0)\) 的取值集合（连同地面哨兵 \(0\)）。只要 \(A\) 满足此不变量，就有 \(\max A = H(x_0)\)——我们追踪 \(A\) 的最大值，等价于追踪 \(H\)。

    不变量也直接规定了在每个边界要做什么，才能从 \(x_0\) 维持到下一个边界：

    • 在 \(x = l_i\)（建筑进入）：\(h_i\) 开始满足 \(l_i \le x\)，应进入 \(A\) → 插入 \(h_i\)。
    • 在 \(x = r_i\)（建筑退出）：\(h_i\) 不再满足 \(x < r_i\)，应离开 \(A\) → 删除 \(h_i\)。
    • 每次更新后，比较 \(\max A\) 与上一次的值。若变了，说明 \(H\) 在此跳变，输出关键点 \((x, \max A)\)。

    哨兵 \(0\) 始终留在 \(A\) 里，保证空集时 \(\max A = 0\) 有定义，并在所有建筑退出后自然输出落地点 \((x, 0)\)。这样，算法的每一步都只是不变量的直接后果，而不变量又是 \(H(x)\) 定义的直接重述——从形式化到算法是一条连续的推导。

    实现：把"插入 / 删除 / 求 max"的多重集落地#

    算法骨架已定，剩下的只是选一个支持插入、删除、求最大值的多重集结构。三种常见实现：

    1. SortedList / multiset / TreeMap：三种操作均 \(O(\log n)\) → 总 \(O(n \log n)\)。最贴合不变量的直接实现，推荐。
    2. Max-Heap + 懒删除：插入 \(O(\log n)\)；删除不立即执行，而是在求 max 时若堆顶已"过期"（其 \(r \le\) 当前 \(x\)）就 pop 掉。每个元素一生只入堆、出堆各一次，摊销 \(O(\log n)\)。Python 用 heapq 存负数模拟大根堆。
    3. 分治 (Divide & Conquer)：仿归并排序，递归求左右两半的天际线再合并，合并 \(O(n)\)，总 \(O(n \log n)\)。它把"两条天际线如何叠加"显式化，但代价是合并步要做对齐与并行扫描的分情况讨论；扫描法则把这部分负担交给了多重集，无需显式分情况。

    排序时的并列处理：从定义推出，而非记忆#

    多个边界落在同一个 \(x\) 时，处理顺序会影响结果，而正确的顺序可以直接从 \(H(x^+)\) 的定义推出，不必死记。

    考虑两栋等高且首尾相接的楼 [[0,5,7],[5,10,7]]。在 \(x=5\)，左楼退出、右楼进入。正确输出应是 \([[0,7],[10,0]]\)——中间高度一路是 \(7\)，\(x=5\) 处不该有关键点。但若在 \(x=5\) 先处理退出（删掉一个 \(7\)），\(A\) 里 \(7\) 的计数瞬间归零，\(\max A\) 掉到哨兵 \(0\)，我们就会误报一个 \((5,0)\)；下一步再处理进入把 \(7\) 加回，又误报一个 \((5,7)\)。两个虚假关键点。

    下图对比 \(x=5\) 两个事件的两种处理顺序：上排（先开始后结束，正确）\(\max A\) 全程为 \(7\) 不跳变；下排（先结束后开始，错误）\(\max A\) 短暂跌到哨兵 \(0\)，凭空多出两个关键点。

    flowchart LR
    Start["x=5 前: A={0,7}, max=7"]

    Start --> R1["先 add 5进入: A={0,7,7}, max=7"]
    R1 --> R2["再 del 5退出: A={0,7}, max=7"]
    R2 --> R3["max 未变 → 不输出 ✓"]

    Start --> W1["先 del 5退出: A={0,7}, max=7"]
    W1 --> W2["max=7→? 仍7, 继续"]
    W2 --> W3["此前若先删尽: A={0}, max=0"]
    W3 --> W4["误报 (5,0) ✗"]
    W4 --> W5["再 add 5进入: A={0,7}, max=7"]
    W5 --> W6["误报 (5,7) ✗"]

    根因在于：关键点取的是 \(H(x^+)\)，即 \(x\) 处"尘埃落定后"的高度。要让 \(\max A\) 在每个 \(x\) 上反映的是该 \(x\) 的最终状态，必须在比较前把同一 \(x\) 的所有进入都做完、再做退出。所以规则是：同 \(x\) 处，先处理所有开始事件，再处理结束事件。

    落实到排序，给每个边界编一个三元组排序键 \((x, \text{key})\)：开始事件用 \((l_i, -h_i)\)，结束事件用 \((r_i, 0)\)。负高度 \(-h_i < 0\) 让开始事件排在结束事件（键为 \(0\)）之前，自动实现"先进后出"；多个开始事件之间，\(-h_i\) 升序即高度降序，让较高的先插入，使每次比较前 \(\max A\) 已是该 \(x\) 的最终值。注意这里的负号是排序编码技巧，进入 \(A\) 的仍是真实高度 \(h_i\)，与不变量一致。

    复杂度#

    • 全部主流解法：\(\Theta(n \log n)\) 时间，\(\Theta(n)\) 空间。
    • 在基于比较的模型下，这是最优的：天际线本身可有 \(\Omega(n)\) 个关键点，给出 \(\Omega(n)\) 的输出下界；而把 \(n\) 个建筑按边界排序，可归约自比较排序，给出 \(\Omega(n \log n)\) 的下界。两者合起来使 \(\Theta(n \log n)\) 不可改进。需注意此 \(\log\) 因子是比较模型的产物——坐标为 \(\le 2^{31}-1\) 的整数时，事件可用基数排序在 \(O(n)\) 内排好，故"必须 \(n\log n\)"仅就比较解法成立。

    陷阱#

    这些陷阱不是孤立的清单，多数可直接从 \(H(x)\) 的定义或不变量推出：

    • 同 \(x\) 处的事件顺序：先开始后结束，排序键 (x, -height)（开始事件高度取负，结束事件排序字段取 \(0\)）。根据见上节——这是 \(H(x^+)\) 取右极限的直接后果，错序会在相接 / 等高场景误报或漏报关键点。
    • 不输出连续相同高度：每次输出前与上一段高度比较，仅在 \(\max A\) 真正变化时才记录。这对应"关键点是 \(H\) 的跳变点"，平段内部不是关键点。
    • 坐标可达 \(2^{31}-1\)：勿用窄类型存横坐标；尤其不能用线段树暴力开 \(2^{31}\) 个叶子（即朴素尝试撞上的第一堵墙），若走线段树路线必须先离散化到 \(2n\) 个边界。
    • 哨兵 \(0\)：始终留在 \(A\) 中，保证 max(A) 永远有定义（空集时为地面 \(0\)），并使所有建筑退出后自然输出落地点 \((x, 0)\)。
