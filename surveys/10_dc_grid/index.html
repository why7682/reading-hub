    §1 Introduction: AI DC as Grid-Interactive Flexible Load#

    1.0 30-Second Reader Self-Check & Elevator Pitch#

    Elevator pitch. AI 数据中心曾被电网当作"不能动的大灯泡"——一种 24/7 满负荷、对电网频率事件透明、不参与 demand response 的 must-run base load。2024–2026 两个独立证据推翻了这一假设：(a) Phoenix 256-GPU 集群在 Nature Energy 公开实测中可以在功率上界基础上压缩 −25 % 持续 3 小时而不爆破 SLO；(b) FERC 在 12/2025 的 PJM Co-Location Order 中要求对大型 flexible load 区分 Firm vs Non-Firm CDS tariff——监管层已经把这类负荷视为"可承诺、可审计、可处罚"的实体。本综述把 AI DC 视为 grid-interactive flexible load (GIFL)，并把现有 10+ 篇综述分别覆盖的"可调度多深"（workload schedulability）、"调度到哪里"（spatial-temporal carbon/water）、"由谁监管怎么记账"（FERC/RTO mechanism）三块同时作为骨架，用 commitment-audit-penalty 博弈 (Williamson 1979 hold-up) 与 cascading-aware Pigouvian signal (Banerjee 1992 herding) 两条概念骨架贯穿。

    2024 年以前，超大型 AI 训练 / 推理数据中心 (DC) 在电力规划层普遍被视为 must-run base load——满负荷接入、不参与 demand response (DR)、对电网频率事件透明。这一假设的三个支柱在 2024–2026 同时松动：

    1. 现场实测层： Turning AI Data Centers into Grid-Interactive Assets: Results from a Field Demonstration in Phoenix, Arizona (Nature Energy 2025/26 online; arXiv:2507.00909；Colangelo, Coskun, Megrue, Roberts, Sengupta, Sivaram, Tiao, Vijaykar, Williams, Wilson, MacFarland, Dreiling, Morey, Ratnayake, Vairamohan, 15 authors) 在 Phoenix 256-GPU 训练集群上首次给出公开可复现的 envelope 实测：据该论文报告，集群可在功率上界基础上压缩约 −25 % 持续 3 小时——本综述凡引用此数字一律以 "−25 % × 3 h 单 envelope 内最大组合" 复述，不可拆开宣称"可任意 3 h 大幅削峰"（见 §6 fact-check 附录）。
    2. 市场机制层： FERC 于 2025-12-18 在 docket EL25-49-000 (PJM Co-Location Order) 中要求 PJM 提交对 large flexible load 的 Firm vs Non-Firm Co-located Demand Service (CDS) 区分 tariff；60-day compliance window 落在 2026-02-16，因当日是 President's Day，PJM 实际于 2026-02-17 提交（FERC fact sheet / PJM docket file 一致确认；早期律所 brief 中的 "1/20" 已被 12/18 order 推翻）。FERC ANOPR RM26-4-000 (2025-10 DOE Secretary Letter → 2026-04-30 DOE 期望的 final action 目标日期) 进一步把 large load interconnection 的 federal 维度推上 docket。其中 GIFL = grid-interactive flexible load（可向 RTO/utility 承诺 envelope 并按 audit 兑现的大型负荷）；FERC EL25-49 = 监管 hyperscaler 与发电厂直接配对的 co-location tariff；LME = 节点级边际碳信号；CMEF = 在 cascading/non-price-taker 下对 MCI 的群体行为修正信号；ELCC (effective load carrying capability) 此处指 data-center load resource 相对其 nameplate 计入 PJM capacity 的可信容量比例。Williamson 1979 hold-up 与 Banerjee 1992 herding 是两个 cross-domain 经济学引用，详见 §9.11 与 §6.6。

    1.2 Scope: Three-Layer Framing#

    本综述采用 Phase 0a 三层 scope：

    • Narrow scope (single site, sub-minute): GPU cluster 在 power-cap / DVFS / BESS coupling 下的物理 envelope (§4–§5)。
    • Mid-tier scope (fleet, hour–day): 跨 region 的 spatial-temporal workload shifting 与 carbon/water-aware 调度 (§6–§8)。
    • Broad scope (federal/RTO, queue–year): FERC docket、RTO tariff、capacity market、co-location 安排在制度层重塑 DC 的 grid-interactive 地位 (§9)。

    mid-tier 是本综述的承重层：narrow 与 broad 单独看都已有较成熟综述，但 mid-tier 把三块缝合的工作仍是 gap。

    2.1 术语精确化#

    术语 定义 (本综述使用义)
    GIFL (grid-interactive flexible load) 可向 RTO / utility 承诺 envelope 并按 audit metric 兑现的大型负荷 (本综述顶层范畴)。
    DCFlex EPRI 主导的 DC flexibility initiative；M8 实测来源之一。
    HILL (highly interruptible load) 可在分钟级响应中断指令的 load 类，本综述用作 DR 中的子类。
    LME (locational marginal emissions) 节点级（per-bus）边际排放强度信号；形式上是 OPF emission constraint 上的对偶变量，与 LMP（power balance 对偶）同源 (B4, Cote & Sun, arXiv:2512.18819)。
    CMEF (cascading marginal emissions factor) 在多个 large flexible load 联动下，单点 MEF 不再 price-taker 时的修正信号 (B5；该论文在 EV 上 instantiate)。
    MCI / AEF (marginal carbon intensity / average emission factor) hourly grid carbon signal 的两种主流形态。
    CDS (Contract Demand Service) FERC EL25-49-000 中 PJM 区分的 Firm Contract Demand transmission service / Non-Firm Contract Demand transmission service 两类 tariff（本综述简称 Firm CDS / Non-Firm CDS）。
    NCBL (non-customer baseline load) PJM capacity market 中针对 large flexible load 的 baseline framework；用于在 capacity 评估时给 large flex load 设定 ex ante 的"未参与 DR 时的 baseline 负荷"基准 (M7)。
    ORDC (operating reserve demand curve) ERCOT 把 reserve 短缺转换为 energy price 的曲线（scarcity-based price 而非显式 capacity market）；M11 报告 Aurora 模拟其失真。
    ELCC (effective load carrying capability) 资源 nameplate 中可计入 capacity 的可信比例；最初为 intermittent generator 设计，PJM 近年扩展到 large flexible load resource。
    DVFS (dynamic voltage/frequency scaling) GPU/CPU 在运行时调节工作电压与频率的功率/性能 knob；本综述把 \(f_n^{\text{GPU}}\) 作为其代表变量。
    PCC (point of common coupling) DC 与 grid（utility 侧）的物理接入点；envelope / audit 通常在 PCC 度量。
    FFR (fast frequency response) sub-second 级响应频率事件的 ancillary service；典型要求秒以下响应 + 10–30 s 持续。
    ANOPR (advance notice of proposed rulemaking) FERC 立法流程中的预通告阶段；早于 NOPR 与 final rule。
    ISA (interconnection service agreement) hyperscaler / load 与 RTO/utility 之间关于接入服务的双边合同；M3 Talen-Amazon ISA 是代表性案例。
    NCCL (NVIDIA Collective Communications Library) 分布式训练中多 GPU 同步梯度/参数的标准库；ring/tree all-reduce 是其两种主要 collective topology，是 sub-second power swing 的来源。
    HBM (high-bandwidth memory) 紧贴 GPU die 的高带宽内存；其温度 \(\theta_n^{\text{HBM}}\) 是 thermal-aware 控制的关键约束。
    co-location DC 与 generator 直接 BTM (behind-the-meter) 配对 (M3 Talen-Amazon Susquehanna ISA case)。
    TTFT / TBT / JCT / SLO time to first token / time between tokens / job completion time / service level objective；LLM inference QoS 的主要度量。

    整合 Phase 0a §5、Phase 0c A/B/C 的符号，按 "集合 → 状态 → 控制 → 信号 → 目标" 五段排列。

    集合与索引：

    • \(\mathcal{D} = \{d_1, \dots, d_N\}\) — 数据中心 site 集合，cardinality \(N\)。
    • \(\mathcal{R}\) — 电网 region / RTO / balancing authority 集合。
    • \(\mathcal{J}_t\) — 时刻 \(t\) 待调度的 AI workload job 集合。
    • \(\mathcal{T}\) — 调度时间步集合，按 sub-second / minute / hour 多尺度细分。
    • \(\mathcal{M} = \{T, LI, BI, FT\}\) — workload 类型：training / latency-critical inference / batch inference / fine-tuning。

    状态与功率变量：

    • \(\mathbf{p}_t \in \mathbb{R}^N\) — 各 site 在 \(t\) 时刻的有功功率向量 (MW)。

    • \(\theta_n^{\text{HBM}}\) — site \(n\) GPU HBM 温度 (热应力约束)。

    控制与调度变量：

    • \(\mathbf{W}_t\) — workload-to-site 分配矩阵，\(W_{j,n,t} \in [0,1]\)（job \(j\) 在 site \(n\) 的分配比例），\(\sum_n W_{j,n,t} = 1\)（每个 job 在 site 集合上的 simplex 分配）。

    信号 (Pigouvian / market)：

    • \(\mathbf{c}_t^{\text{region}} \in \mathbb{R}^{|\mathcal{R}|}\) — region 级实时碳强度信号 (kgCO\(_2\)/MWh)，可为 MCI / AEF（RTO/BA 粒度，\(|\mathcal{R}|\) 量级 10s）。
    • \(\mathbf{c}_t^{\text{LME}} \in \mathbb{R}^{|\mathcal{N}_{\text{bus}}|}\) — locational marginal emissions，节点（bus）级（B4，\(|\mathcal{N}_{\text{bus}}|\) 量级 \(10^3\)+；本综述用投影 \(\Pi_{R\to N}\) 把 region 信号映射到节点）。\(\mathbf{c}_t\) 在无下标时默认 region 级。

    • \(\boldsymbol{\lambda}_t\) — LMP 或 LMP+LME 联合价格向量。
    • \(\boldsymbol{\mu}_t\) — water stress / WUE 信号。
    • \(\mu_t^{\text{wb}}\) — wet-bulb-driven hourly water intensity (T5 桥接候选信号)。
    • \(\sigma_t\) — scarcity / ORDC 价格信号 (M11)。

    目标与 QoS：

    • \(q_j(\mathbf{p}, \mathbf{W})\) — job \(j\) 的 QoS 函数 (throughput, JCT, TTFT, TBT, accuracy)。
    • \(\eta_n^{\text{PUE}}, \eta_n^{\text{WUE}}\) — site \(n\) 的 PUE 与 WUE。
    • \(\mathcal{L}(\cdot)\) — 多目标损失： $\(\mathcal{L} = w_1 \cdot (\boldsymbol{\lambda}_t^\top \mathbf{p}_t) + w_2 \cdot (\mathbf{c}_t^\top \mathbf{p}_t) + w_3 \cdot (\boldsymbol{\mu}_t^\top \mathbf{p}_t) + w_4 \cdot \text{QoSPenalty}(\mathbf{W}_t, \mathbf{p}_t).\)$
    • \(V^{\text{commit}}, V^{\text{audit}}, V^{\text{penalty}}\) — T3 commitment game 三要素：承诺价值 / 审计度量 / 违约罚。

    符号歧义注： \(\bar{p}_n\) 物理上限 与 envelope 承诺上界 \(\bar p_n^{\text{env}}\) 在不同上下文使用，引用时通过 subscript 区分。

    2.4.1 6-Axis Taxonomy 选择理由#

    本综述选取 6 axes（time-scale / spatial-scale / control-hierarchy / objective / signal / mechanism）的理由如下：

    • time-scale: AI DC 灵活度跨越 µs (sub-second GPU swing) 至 year (interconnection queue) 共 12+ 数量级；time-scale 是最基础的分类轴。
    • spatial-scale: single site / fleet / RTO / federal 四层 spatial 视角是 Thread A / B / C 各自工作的差异核心。
    • control-hierarchy: workload-level / facility-level / RTO-level 三层 control hierarchy 决定了"谁是 control authority"——这与 mechanism 中的 commitment 结构直接挂钩。
    • objective: energy / SLO / carbon / water / cost / reliability 等多目标的相对权重决定了 control loss 设计；本综述统一 \(\mathcal{L}\) 形式（§2.2）就是为了让这一轴可比较。
    • signal: $\Delta f / $ price / MCI / LME / CMEF / water / scarcity 等信号类型直接决定 mechanism 的 Pigouvian 形式。
    • mechanism: voluntary DR / ancillary market / capacity baseline / tariff classification / co-location 等机制类型是 Thread C 的核心轴。

    未选取的候选 axes（如 hardware-centric vs software-centric、operational vs embodied、temporal vs spatial）多为二元分类，缺乏跨论文 differentiating power；本综述判定 6 axes 已能 capture 多数 cross-paper 差异。

    §3 AI Workload Schedulability & Heterogeneity (Thread A 主)#

    3.1 三类 workload 的 (preemptibility, restore cost, response latency) 三元组#

    AI DC 内 workload 不可视为同质 batch；至少需区分三类：

    类型 一阶 \(\alpha_j\) restore cost \(R_j\) response latency \(\delta_j\) preemptibility 二阶约束 \(\alpha'_j\)
    Training (T) 形式上 \(\alpha \approx 1\)（可 checkpoint），实际受 NCCL collective 拓扑限制 \(R\) 随 checkpoint size \(C\) 与 model parallel degree 增长 中（sec–min） NCCL ring/tree topology 上 partial preemption 不安全；hypergraph 二阶
    Latency-critical inference (LI) \(\alpha \approx 0\) 至 \(0.2\)（SLO 紧） 几乎为 0（无状态） 极低 (ms 级 TTFT) 跨副本 load balancing 几乎独立，二阶弱
    Batch inference (BI) \(\alpha \in [0.5, 0.9]\) 低 中 (sec–min) request 间独立，几乎可视一阶
    Fine-tuning (FT) \(\alpha \approx 0.5\)–\(0.8\) 中 中 介于 T 与 BI 之间

    Seam δ (拓扑感知 preemptibility): Phase 0c A 指出，几乎所有 Thread B 综述把 workload 当作 (α 一阶标量) 处理；但 training 的可中断性受 NCCL ring / tree collective 拓扑约束，是 hypergraph 二阶量 \(\alpha'_j\) 而非标量。本综述把 \(\alpha'_j\) 作为 §10.1 桥接的核心变量之一。

    3.2 Checkpoint Scaling Law 现状#

    Checkpoint scaling 是 \(R_j\) 的核心驱动。据已 verify 的 A1 (Phoenix) 在 256 GPU 上记录的 envelope 实测，checkpoint frequency 与 restore time 的乘积 budget 是 training-DR 兼容性的关键指标，但目前学术文献中尚无统一的 R(N, G, C) scaling law 形式化——这是 Open #5 的核心 gap。M4 (Chen & Zheng, arXiv:2604.05376) 在 defer-vs-shift framing 中已点出 queue 期 commitment 与 training preemption 的 IC 问题，但未给出 R 的 closed-form。

    3.3 NCCL Collective 的二阶拓扑约束#

    大型 LLM training 普遍依赖 NCCL ring-allreduce 或 tree-allreduce；据 A2 该论文 (Choukse et al., Microsoft Azure team, arXiv:2508.14318) 报告，sub-second 级 GPU power-cap 变化会通过 collective sync barrier 放大为整集群级功率 swing。本综述把这一现象在 §5 进一步展开。

    3.3.1 Communication Pattern 与 Power 关系#

    NCCL collective 的不同 pattern（all-reduce / all-gather / reduce-scatter / broadcast）在 power profile 上差异显著：

    • all-reduce (ring): 分 \(2(N-1)\) 步、每步只与邻居通信；持续同步时间最长，集群级 swing 持续覆盖整个步序；
    • all-reduce (tree): 在 root 节点形成瞬时聚集，瞬时峰值最高但持续较短；
    • reduce-scatter / all-gather: 半同步，swing 较小；
    • point-to-point: 几乎独立，swing 接近 noise floor。

    直观上：NCCL ring/tree 的作用是让上百到上千个 GPU 在每一步 backward pass 后把梯度求和并广播——所有 GPU 必须在 sync barrier 处对齐，谁先到就等，等的瞬间 GPU 几乎 idle、功率骤降，等够再一起恢复，这就是 sub-second 100s MW swing 的成因。

    LLM 训练在 tensor / pipeline / data 三种 parallelism 不同组合下使用的 collective pattern 不同，因此 sub-second swing 强度因 model architecture 而异。这一异质性在 A2 (Choukse et al., Microsoft Azure team) 已隐式触及，但未给出 model-architecture-dependent envelope 的量化对照——是 Open #1 的子部分。

    3.3.2 异质性如何映射到 Grid-Side 视角#

    从 grid 视角看，三类 workload 形成不同的 "load 特征指纹"：

    • Training-class load: 稳态高功率 + sub-second collective swing；适合贡献 "可承诺 baseline shedding" 而非 fast frequency response。
    • Latency-critical inference load: 请求驱动 burstiness + 严格 SLO 不可中断；从 grid 视角是 "must-serve" 类，对 DR / capacity market 的 ELCC 贡献低。
    • Batch inference load: 中等 burstiness + 灵活 SLO；最贴合传统 DR / capacity baseline 程序的 load 类型。
    • Fine-tuning load: 介于 batch inference 与 training 之间。

    这一指纹差异使得"AI DC 占电网比重 X %"这类粗粒度 forecast（如 PJM 2025 forecast 报告中的 94 % data center 占比，按 §6.2 hedge）实际上 conflate 了不同 load 类型的 grid 影响。本综述强烈建议 future RTO load forecast 把 AI DC load 细分到 workload class 层面——这一建议也是 §11 Open #3 的支撑论点。

    3.4 Schedulability 与 Grid-Interactive 的耦合#

    A1 Phoenix 实测 (15 authors, Nature Energy 2025/26 online) 在 single envelope 内验证：256-GPU 集群在压缩 \(\sim\) 25 % 功率 3 小时下，throughput 损失被控制在可接受范围（具体 SLO 含义见该论文表格，本综述不擅自外推）。A13 (Zhang, Wilson, Paschalidis, Coskun, IEEE TSUSC 7:157–171, 2022) 在 HPC 场景已建立 adaptive cap with QoS assurance 的方法学基线；但 A13 是 HPC 而非 GPU/LLM，迁移到 AI DC 需 §10.1 schedulability-aware shifting 重新建模。

    3.5 Workload 异质性对 Thread B 信号设计的影响#

    Thread B 的 carbon-aware shifting 文献几乎全部把 workload 视为同质 batch，这与 §3.1–§3.4 的实际三类异质性存在系统性失配。具体而言：

    • Training-class job 在跨 region spatial shifting 中受到 NCCL 拓扑限制，无法被随意切分；该论文 (A2, Choukse et al., Microsoft Azure team) 的 sub-second swing 实证表明，即使在同一 site 内部，collective sync barrier 也已经把 training 的"瞬时灵活度"绑死。
    • Latency-critical inference 的 \(\alpha \approx 0\) 意味着即使 carbon signal 给出强烈的 shift 指令，调度器也必须先满足 SLO；这与 B7 (该论文 作者待 verify) 假设的 "1 % flex" 边际形成矛盾——SLO 约束下的"实际可 flex 比例"在不同 SLO budget 下差异极大。
    • Batch inference 是当前 Thread B 文献最贴合的工况，但其在大规模生产部署中通常被划入低 priority 队列，在 cascading 信号 (§6.1) 下，"低优先级"自身会被 RTO 视为可中断——结果是 B5 (Nat. Commun. cascading-EV 作者待 verify) 在 EV 上观察到的"signal 同步淹没现象"在 batch inference 上可能更严重。

    本综述把这三点作为 §10.1 形式化的 motivation。

    3.6 Schedulability 与 Audit Metric 的对接#

    将 §3 的 schedulability 三元组 \((\alpha_j, \tau_j, R_j)\) 与 §9 M9 envelope 四元组 \((\bar p, \underline p, T_{\text{response}}, T_{\text{sustain}})\) 对接是本综述的关键 stitch。具体而言：

    • \(T_{\text{response}}\)（envelope 响应时长）必须 \(\ge \max_j R_j\) on the critical path，否则 audit 时 RTO 观察到的 actual power trajectory 会因 restore 抖动而 fail 罚款门槛。
    • \(T_{\text{sustain}}\)（envelope 可持续时长）必须考虑 training job 的 checkpoint 周期：若 \(T_{\text{sustain}}\) 跨越一个 checkpoint 周期，restore cost \(R_j\) 翻倍。
    • envelope 上下界 \((\bar p, \underline p)\) 的比值在 §4.5 中估算为约 1.33 (Phoenix 实测)，但这一比值在 inference-only fleet 上可能更宽，在 training-dense fleet 上更窄。

    这一对接关系在公开文献中尚未被系统建模——既不在 Thread A（A1 给参数但未对接 audit 语义）也不在 Thread C (M9 给 audit 语义但未对接 schedulability)。本综述把它作为 §10.5 stitch 的承重论点之一。

    3.7 Training 的 Restart 经济学#

    training 的 preemption 经济学不仅是 checkpoint-restore 时间，还涉及 GPU 折旧、电力机会成本与 model convergence 风险三个维度：

    • GPU 折旧机会成本： 大型训练集群的 GPU 资本支出极高，preempt 期 GPU idle 直接对应折旧浪费；该折旧 / 小时 在 hyperscaler 内部财务模型中比 utility DR 补偿高 1-2 个数量级（具体数字商业敏感，本综述不给点估计）。
    • 电力机会成本： preempt 释放的功率若被卖给 ancillary market，会有正向收益；这一收益与 LMP / scarcity 信号 \(\sigma_t\) 相关，且在 ORDC 失真 (§6.8 / §10.3) 下不稳定。
    • convergence 风险： 大型 LLM training 在某些临界 batch 间隔被 preempt 后可能 fail to converge 或需要 hyperparameter 重调；这一风险在公开文献中几乎无定量数据，属于 hyperscaler 内部 know-how。

    把这三个维度联合代入 M4 (Chen & Zheng) 的 defer-vs-shift framing，能看出 defer 的"机会成本"比 simple downtime 复杂得多——这是 Open #5 与 Open #3 的交叉点。

    3.8 Inference Workload 的请求驱动 burstiness#

    inference workload 的 power profile 由请求 arrival 与 KV cache 占用驱动，呈现出明显的 burstiness。该 burstiness 在 grid-side 表现为：

    • 短时（秒级）功率 spike 在 facility 侧由 BESS / GPU firmware 平滑；
    • 中时（分钟级）由 autoscaling 与 load balancing 平滑；
    • 长时（小时级）由 request 业务模式（白天高、夜晚低）决定。

    A6 / A8 / A9 phase-aware DVFS 主要在短时尺度上 attack burstiness；spatial-temporal shifting (Thread B) 主要在长时尺度上 attack。而中时尺度的 mechanism（如 A11 reshape）在跨 RTO 部署时受到 §5.6 BESS 经济性差异约束。本综述把这三个尺度的 burstiness 处理视作一个 control hierarchy 的同构问题。

    §4 Power-Capping, DVFS & Phase-Aware Control Envelope (Thread A 主)#

    4.1 Oversubscription Headroom: Training vs Inference#

    A3 (Patel et al., Microsoft Azure / UW, ASPLOS '24, DOI 10.1145/3620666.3651329) 在其特定 cluster + model 组合下报告了关键的不对称：据该论文报告，training 工况下的功率 oversubscription headroom 约为 3 %，而 inference 工况下可达 21 %。这里 "oversubscription headroom" 指 cluster 实际平均功率与 nameplate 之间的差距——方向是 nameplate 之下、供电系统可超配的余量；training 在 collective sync 节拍上的功率 spike 几乎贴满 nameplate，余量小；inference 的请求驱动 burstiness 留出更多余量。本综述凡引用此数字一律以 "A3 specific cluster + model 组合下的实测，不可泛化为通用上限" 复述（fact-check 见 §6.2）。

    4.2 DVFS Knob 与多目标控制#

    A4 POLCA (arXiv:2308.12908) 与 A5 DynamoLLM (Stojkovic, Choukse, Bansal, Gandhi, Cidon et al., HPCA '25 / arXiv:2408.00741) 把 DVFS 与 cluster-level scale-in/scale-out 联合作为 control hierarchy 的两层 knob。据 DynamoLLM 该论文报告，在同实验设定 best case 下可实现 −53 % 能耗 / −38 % CO\(_2\) / −61 % cost——本综述按 §6.2 hedge：这是同实验 best case，不可作为通用广告，引用须锚定 HPCA '25 final version 数字。

    4.2.1 Cluster-Level Scale Knob 的延迟与收益权衡#

    scale-out（增加副本）与 scale-in（减少副本）是 cluster-level 的功率 knob，对 inference 工况尤其重要。但 scale knob 在以下三方面有延迟与收益的非线性权衡：

    • 冷启动延迟： scale-out 一个新副本通常需要 GPU memory 加载、KV cache warm-up 等操作，典型延迟在 sec 级；若在 SLO budget 紧时执行 scale-out 反而会触发 SLO 违约。
    • 能耗对应的非线性： scale-in 释放一个副本节省的能耗与该副本之前的实际利用率非线性相关；utilization 接近 0 的副本几乎无能耗节省，utilization 高的副本节省显著。
    • 负载均衡瞬态： scale 动作后 load balancer 重新分配请求需要时间，瞬态期 SLO 抖动是普遍现象。

    这三方面在 A4 POLCA 与 A5 DynamoLLM 的设计中均有处理，但具体的 scaling 决策 latency 与 SLO 影响的量化数据多为同实验 best case，本综述按 §6.2 hedge 不外推。

    4.3 Phase-Aware DVFS (prefill vs decode)#

    LLM inference 的 prefill 与 decode 阶段在 arithmetic intensity 上差异极大；A6 (throttLL'eM, 作者待 verify)、A8 (GreenLLM, 作者待 verify)、A9 (DualScale, Basit, Liu, Kong, Hu, Purdue, arXiv:2602.18755, 2026) 把 \(\phi_j \in \{\text{prefill}, \text{decode}\}\) 加入 DVFS / 放置决策（prefill compute-bound、decode memory-bound 受 KV cache 主导）。其控制律可写为：

    \[f_n^{\text{GPU}}(t) = \pi_\theta\big(\phi_j, \text{KV cache len}, \text{SLO budget}, \mathbf{c}_t, \boldsymbol{\lambda}_t\big).\]

    这一形式化在三篇论文中具体参数化不同；本综述对每篇的具体 reduction 数字一律以 "该论文报告"+保留区间方式引用。

    4.4 Thermal-Aware Placement (TAPAS)#

    A7 TAPAS (传 Stojkovic et al. ASPLOS '25, 待 verify) 以 \(\theta_n^{\text{HBM}}\) 为约束做 placement + cap 联合优化，与 A3–A6 的电能 knob 形成 thermal-electrical 双联控制。其与 A11 reshape (该论文 Adv Appl Energy 作者待 verify) 的差异在于：TAPAS 内部最优化 SLO + thermal；A11 则把 reshape 当作 grid 友好的 output side knob。

    4.5 Envelope Quantification: 与 Phoenix 实测对接#

    本综述把 §4.1–§4.4 的 DVFS / cap / placement / reshape 视为 A1 Phoenix envelope 的 internal degrees of freedom。Phoenix envelope 在 single site 层面观察到 \(\bar p / \underline p \approx 1.33\)（−25 % depth；该论文报告，envelope ratio 数字 hedge 见 §6.2）；该 envelope ratio 可由 §4.1–§4.4 的 knob 组合实现，但具体 mapping 在公开文献中尚未完整建模——这是 §10.3 的 stitch 入口。

    4.6 Phase-Aware 与 Throughput-QoS 权衡#

    LLM inference 的 prefill 与 decode 的硬件压力差异在 phase-aware DVFS 文献中已被反复实证：prefill 阶段 compute-bound、对 GPU 频率敏感、对 KV cache 不敏感；decode 阶段 memory-bound、对 HBM 带宽敏感、对 KV cache 长度敏感。这一区分使得 phase-aware DVFS 可以在不损失 SLO 的前提下榨取额外能耗 / 碳收益。然而，phase-aware DVFS 在 batch sharing 与 continuous batching 工况下的有效性受到 batch composition 影响——同一时刻的 batch 内若 prefill 与 decode token 混杂，phase-aware knob 退化为整体 DVFS。这一退化场景在 A6 / A8 / A9 三篇中均有提及，但没有联合给出 batch-composition-dependent reduction 曲线——这是 §4 内部的小 gap。

    4.7 Power-Cap 的非线性 SLO 边界#

    A3 / A4 / A5 给出的 oversubscription 数字（3 % / 21 %）背后是一个非线性 SLO 边界：当 cap 压得过深时 SLO 违约率不是线性增长，而是在某个临界点突然陡升。该论文 (A3) 报告该临界点与 model 的 critical batch size 相关；本综述不擅自外推到通用 model family。这一非线性边界对 §10.5 audit 设计的含义是：M9 envelope 的 \(\underline p\) 不应被设为接近临界点的值，否则 audit 期 SLO 抖动会传播为 grid-side 罚款风险。

    4.8 与 Thread C M9 Envelope 的语义对接#

    §4.1–§4.7 共构成 envelope 的 internal degrees of freedom，但 M9 (Utility Dive piece 作者待 verify) 提出的 envelope audit 四元组 \((\bar p, \underline p, T_{\text{response}}, T_{\text{sustain}})\) 是 external visibility 的语义。两者的 mapping 是：

    • 内部 DVFS / cap / placement / reshape knob 组合 → 外部 envelope shape；
    • 内部 thermal / SLO / collective sync 约束 → 外部 envelope feasibility；
    • 内部 oversubscription headroom → 外部 envelope ratio 上限。

    把内部 knob 与外部 envelope 显式 mapping 的工作在公开文献中尚未完成。本综述把它列为 §11 Open #3 (跨 RTO 统一 audit metric) 的子部分。

    4.9 DVFS Knob 与 SLO 的非交换性#

    phase-aware DVFS 与 cluster-level scale knob 在多个 knob 同时操作时非交换：先 DVFS 再 scale 与先 scale 再 DVFS 在 SLO / 能耗上结果不同。这一非交换性的根源是 KV cache 在 scale-out 时的 cold start 重建成本与 DVFS 频率对 cold start 时间的影响共同作用。该论文 (A5 DynamoLLM, Stojkovic + Choukse et al., HPCA '25) 在其 control hierarchy 设计中已隐式处理这一非交换性，但本综述强调：在跨集群 / 跨 site 的 spatial shifting 决策（Thread B）中，这一非交换性会被进一步放大——一个 spatial shift 动作 实际上是 (scale-out at destination) + (scale-in at source) + (DVFS 全局调整) 三 knob 联动，order 与 timing 都会影响实际能耗 / 碳收益。

    4.9.1 多 Knob 控制策略的 Search Space 复杂度#

    §4.1–§4.9 涉及的 control knob 至少包括：DVFS frequency、cluster scale (in/out)、phase-aware DVFS、thermal placement、reshape batch size、checkpoint frequency、collective topology 选择等 7+ 维度。每个 knob 又有连续或离散的取值空间。多 knob 联合控制策略的 search space 极其庞大，传统 grid search 不可行。

    主流方法包括：

    • 启发式 + 经验规则: A3 / A4 早期工作；可解释性强但难以达到最优。
    • 强化学习: A5 DynamoLLM 采用 RL-based scheduler；性能好但训练成本高、解释性弱。
    • MPC + 凸优化松弛: A12 Ren et al. 类工作偏向 model-based；要求系统模型准确，AI workload 系统模型本身有不确定性。
    • 混合方法: 多数生产系统采用启发式 + ML 混合策略。

    把多 knob 联合控制与 §10.1 跨 thread 统一目标函数 \(\mathcal{L}\) 对接，是 future control-theoretic 工作的核心议题之一。

    4.10 Power Capping 与 Carbon Signal 的耦合滞后#

    §4.1–§4.9 的 control knob 都在 sec–min 尺度生效，而 carbon signal (§6) 多为 hourly 粒度。当 signal 更新时刻与 power cap 执行时刻不同步时，会出现"滞后跟随"现象：cap 在 signal 已经过去后才生效，错过最佳 carbon-aware shifting 时刻。该论文 (B2 EuroSys 作者待 verify) 的 spatial shifting 上限实证可能正受这一滞后影响——若 signal 提供更细粒度（如 5-min），实际 reduction 上限可能突破 20–35 % 区间。但本综述按 §6.2 hedge 不擅自外推。

    §5 Sub-Minute & Sub-Second Physical Boundaries (Thread A 主)#

    5.1 Microsoft Azure Power Stabilization (A2)#

    A2 Power Stabilization for AI Training Datacenters (Choukse, Warrier, Scot Heath et al., Microsoft Azure team — full author list per arXiv:2508.14318) 是当前公开文献中关于 µs–sub-min training swing 的少数实证之一。本综述按 §6.1 处理：引用以 "Choukse et al. + Microsoft Azure team" 表示，不列不完整作者群。据该论文报告，AI training workload 在 collective sync barrier 上会产生 sub-second 级 100s of MW 功率 swing；facility 侧通过 BESS + GPU firmware 联合控制把 swing 压制在 grid 可接受范围。本综述强调：该实测是 facility 私有验证，学术界尚无可复现的公开 envelope——这是 Open #1 的核心 gap。

    5.2 LLM Training Transients (A10)#

    A10 LLM Transients (传 Lin et al., arXiv:2409.11416, 作者待 verify) 给出 LLM training 在不同 batch size / pipeline degree 下的 transient profile。结合 A2，可以观察到 sub-second power swing 的频谱与电网 critical frequency 存在共振风险——这一结论需复述论文的频谱图，不可外推到 "GPU swing 一定会触发频率事件"。

    5.3 Frequency Response Provider 资格的物理边界#

    A12 (Ren, Sun, Wang, Harrison, arXiv:2510.01050) 在 UC + DC as fast frequency response (FFR) 的 grid-side modeling 中刻画了 DC 作为 FFR provider 的 system cost (nadir) 收益；但本综述按 §6.4 hedge：A12 的 DC 模型粒度粗，"GPU 可做 FFR" 是不合理倒推，必须配合 A2 facility 侧 envelope 才能落地。

    5.4 Sub-Minute 与 Sub-Second 的耦合#

    A2 (sub-second) + A10 (sub-min transients) + A12 (RTO 侧 FFR modeling) 共同勾勒出一条"物理边界曲线"，但三者的耦合层级 (facility BESS / GPU firmware / RTO market 资格) 在文献中分散：

    \[\text{Envelope}(\bar p, \underline p, T_{\text{response}}, T_{\text{sustain}}) \xleftarrow[\text{Phoenix}]{T_{\text{sustain}} \sim 3\mathrm{h}} \text{A1} \quad \text{vs} \quad \xleftarrow[\text{A2/A10}]{T_{\text{response}} < 1\mathrm{s}} \text{Microsoft / 传 Lin et al.}\]

    \(T_{\text{response}}\) 与 \(T_{\text{sustain}}\) 在公开文献中尚未在同一篇 paper 内联合实测。这是 §10.5 桥接的核心。

    5.5 Reshape (A11) 作为缓冲层#

    A11 reshape (Adv Appl Energy, 作者待 verify) 在 sec–min 尺度通过 batch / DVFS / scheduling 联合 reshape 输出功率曲线，使其对电网更友好。reshape 与 A2 sub-second BESS 不在同一时间尺度，但二者结合可形成 "fast-BESS + slow-reshape" 二层缓冲，使 envelope \((\bar p, \underline p, T_{\text{response}}, T_{\text{sustain}})\) 四维都可控。

    5.5.1 与 Inverter-Based Resources 的频域共振#

    电网在高 inverter penetration 下（光伏 / 风电 / BESS 大量并网）的频域响应特性与传统同步发电机不同。AI DC 的 sub-second swing 在 inverter-dominated grid 上的影响可能加剧——inverter 的快速响应缺乏同步发电机的物理 inertia 缓冲，swing 直接传导为频率事件。

    这一现象在 RTO 仿真文献中已有初步讨论（不在本综述参考范围内），但与 AI DC 的特殊功率特性结合分析的工作几乎缺位。Open #1 (sub-second envelope) 的研究若忽略 inverter-based resources 的存在，得到的 envelope 可能在未来 grid 上不再适用。

    5.6 BESS 耦合的成本-灵活度权衡#

    facility BESS 是 §5.1 sub-second envelope 的关键支撑硬件。其经济性来自 (a) 削峰节省 utility demand charge；(b) 出售 ancillary service；(c) 缓冲 sub-second swing 以避免 grid-side 罚款。这三类收益的相对权重在不同 RTO 下差异显著：PJM 的 capacity market (M7 NCBL framework) 给 BESS 提供 capacity value，而 ERCOT (M5) 没有正式 capacity market，BESS 主要靠 energy + ancillary 收益。该差异意味着 A1 / A2 / A11 的 reshape 策略在跨 RTO 部署时不能直接复用，必须针对各 RTO 的市场结构重新参数化——这一观察将在 §9.10 与 §10.4 进一步展开。

    5.7 LLM Training Swing 与电网 Critical Frequency 的共振风险#

    A10 (传 Lin et al., arXiv:2409.11416 作者待 verify) 给出的 transient profile 显示 LLM training 的 sub-second swing 在频域上可能与电网 critical frequency 区间存在重叠风险。但本综述强调：

    • "存在频域重叠" 与 "会触发频率事件" 之间需要 grid-side 模型才能 bridge；
    • A10 是 facility-side 实证，未与 RTO inertia / governor response 模型对接；
    • A12 (Ren, Sun, Wang, Harrison, arXiv:2510.01050) 在 RTO 侧建模但未与 A10 facility 侧 swing 数据联合校验。

    把 A10 facility swing × A12 RTO inertia 在同一框架内联合校验，是 Open #1 的具体子目标。

    5.8 Sub-Second 与 Sub-Minute 物理边界的 envelope 投影#

    把 §5.1–§5.7 内容投影到 M9 envelope 四元组上：

    • \(T_{\text{response}}\)：sub-second 由 BESS + GPU firmware 决定，典型 \(\sim\) ms；sub-minute 由 reshape 决定，典型 \(\sim\) 30–60 s；
    • \(T_{\text{sustain}}\)：sub-second 受 BESS energy capacity 限制 (typical 数分钟)；sub-minute 受 thermal / SLO 限制 (typical 数十分钟到数小时)；
    • \(\bar p / \underline p\) ratio：sub-second envelope 较窄；sub-minute envelope 由 A1 实测约 1.33。

    这一投影揭示一个关键事实：单一 envelope 四元组不足以同时描述 sub-second 与 sub-minute 两个尺度的灵活度——可能需要 nested envelope 或 multi-scale envelope 形式化。这是 §11 Open #1 与 Open #3 的合流点。

    5.9 GPU Firmware 控制层的可观测性边界#

    A2 (Choukse et al., Microsoft Azure team, arXiv:2508.14318) 强调，sub-second power stabilization 的核心控制层在 GPU firmware 内部。这一层对外部（utility / RTO）几乎是黑盒：

    • 控制律具体形式不公开（商业敏感）；
    • 控制带宽、响应时间常数等参数没有公开 spec；
    • 不同 GPU 厂商 / 不同硬件代际之间控制语义差异显著。

    这意味着 RTO 即使想 audit sub-second envelope，也面临 metering 与 telemetry 的根本性可观测性差距。当前 FERC / NERC 框架下的 metering 标准基于秒级 / 分钟级抽样，与 sub-second envelope 在时间分辨率上至少差 2-3 个数量级。要把 sub-second envelope 纳入 audit 范畴，metering 标准本身需要升级——这是 Open #1 的 regulatory 子部分。

    5.9.1 GPU 集群级 Telemetry 与 RTO Visibility Gap#

    把 GPU 内部 telemetry 数据传递到 RTO 的链路通常包含以下几层：

    1. GPU 硬件计数器（每 GPU 内部，纳秒级原始数据）；
    2. 集群管理软件（如 Kubernetes / Slurm 层，秒级聚合）；
    3. facility 监控（DCIM 系统，分钟级聚合）；
    4. utility metering（典型 15 分钟 interval）；
    5. RTO scheduling / settlement system（5 分钟或小时级）。

    每一层都做时间聚合，导致 RTO 端的观察粒度远粗于 facility 内部实际控制粒度。RTO 若想 audit sub-second envelope，需要让 telemetry 数据穿透四个聚合层级——这一改造在隐私（hyperscaler 工况是商业敏感）、标准化（不同 hyperscaler 内部架构差异巨大）与基础设施（metering 硬件升级成本）上都有显著挑战。本综述把 telemetry visibility gap 列为 §11 Open #1 与 Open #3 的共同支撑子问题。

    5.10 Critical Frequency 与 ROCOF 的物理约束#

    电网频率稳定性的两个核心约束是：critical frequency (典型在 60 Hz 系统中约 59.5–60.5 Hz 是 normal band，59.0–59.5 是 alarm) 与 ROCOF (rate of change of frequency)。AI DC 的 sub-second swing 在两个约束上都可能产生影响：

    • 数百 MW 级的瞬时功率变化可触发对应规模的频率变化；
    • swing 频谱与 grid inertia / governor response 时间常数的关系决定了 ROCOF 是否超标。

    A12 (Ren, Sun, Wang, Harrison, arXiv:2510.01050) 在 UC 框架下把 DC 视作 fast frequency response (FFR) provider，潜在含义是 DC swing 不仅是 grid 的潜在威胁，也可被设计为 grid 的稳定性资源。这一双面性是 §10.5 stitch 的物理基础——同一物理变量（GPU 功率）在没有 audit envelope 时是威胁，在有 envelope 与 mechanism 时是资源。

    §6 Carbon Signal Design: From MCI to LME to Cascading-Aware Mechanisms (Thread B 主)#

    6.0 桥接 §5 → §6：从物理 envelope 到信号驱动#

    §5 给出的 envelope \((\bar p, \underline p, T_{\text{response}}, T_{\text{sustain}})\) 描述了 GPU cluster 在物理上"能动多少、动多快、动多久"，但没有回答"应该向哪边动、什么时候动"。后一类问题的答案完全由外部 signal 提供——价格、频率、碳、水。本节聚焦其中碳信号这一支：它在过去十年从一个 annual 静态会计指标演化为 nodal 实时调度信号，但每一代信号都暴露出上一代的盲区，每一代修补又引入新的失败模式。

    6.0.1 信号谱系的故事：AEF → MCI → LME → CMEF 修了什么 bug#

    四代信号不是"四个平行选项"，而是一条"修 bug 修出来的"演化链：

    1. AEF (average emission factor) 的 bug： 早期 carbon accounting 用 annual 或 hourly 的"全网平均排放强度"作 signal——但 shifting 1 MWh workload 到低 AEF 时段并不一定减少 1 MWh × ΔAEF 的实际排放，因为被替代下来的边际机组可能是另一类（如水电而非煤电）。AEF 把"会计算账"与"物理减排"搞混。
    2. MCI (marginal carbon intensity) 修 AEF： 改用"此刻新增 1 MWh 会触发的边际机组排放"。这一步把 signal 从会计层升级到调度层，使 spatial-temporal shifting 的边际减排可以与 OPF 替代机组耦合。但 MCI 假设 hyperscaler 是 price-taker——单个 hyperscaler 的 shift 不改变边际机组的 stack 顺序。
    3. LME (locational marginal emissions) 修 MCI： MCI 通常给到 region / BA 粒度，但同一 region 内部不同 bus 的实际边际机组可能完全不同（transmission constraint 导致）。B4 (Cote & Sun, arXiv:2512.18819) 在 1493-bus Western Interconnection 上把信号下沉到 nodal 粒度，类似 LMP 与 OPF emission constraint 的对偶变量。这一步把"shifting 该送到哪一个 bus"变得可解。
    4. CMEF (cascading marginal emissions factor) 修 LME / MCI： 当 hyperscaler 群体规模相对 grid 上升（PJM 2035 forecast 中 data center 占比 94 %，按 §6.2 hedge），单个 hyperscaler 不再 price-taker——所有 hyperscaler 同时看同一 signal 同时 shift，会反过来改变 signal 本身（Banerjee herding × Pigouvian signal）。B5 在 EV 大规模充电上 instantiate cascading 现象，提出 group-staggered CMEF。这一代信号还在概念阶段，DC fleet 上的迁移未学术验证。

    四代信号修补的共同主题是：signal 越精细，price-taker 假设崩溃得越早。§6.1 给出形式化谱系；§6.1.1 解释为何 Pigouvian 经典框架需要被改造；§6.6 把 Banerjee herding 具体 instantiate 到 carbon-aware shifting；§6.8 把同一失效模式映射到 capacity / scarcity 市场以形成跨市场层 mechanism taxonomy。

    6.1 信号谱系: AEF → MCI → LME → CMEF#

    carbon-aware DC 调度的信号设计在 2018–2026 经历了四步进化：

    1. AEF (average emission factor): B1 该论文 (传 Google 2022 tech report, 作者待 verify) 早期使用；存在 "scope-2 actionable 与否" 的 critique (B3 = Wiesner & Kao, Moving Beyond Marginal Carbon Intensity, arXiv:2507.11377；critique 靶点是 MCI 同时作为 carbon accounting 与 grid flexibility 度量的不充分)。
    2. MCI (marginal carbon intensity): B2 (EuroSys, 作者待 verify) 等转向 hourly MCI，使 shifting decision 与系统替代发电耦合；据该论文报告，spatial-temporal shifting 的可达减排上限约为 temporal 5–15 % / spatial 20–35 %——本综述按 §6.2 hedge：高度依赖 baseline 区域与 carbon-signal 提供商，引用须复述 dataset。
    3. LME (locational marginal emissions): B4 (Luc Cote, Andy Sun, Locational Marginal Emissions for Carbon-Aware Data Center Operations in Large-Scale Power Grids, arXiv:2512.18819) 在 1493-bus Western Interconnection 上把信号下沉到 nodal 粒度；据该论文报告，LME-guided intervention 的实测排放削减与真实削减的 accuracy 约 ≥ 85 %（论文原话为 "intervention accuracy with respect to actual emission reduction"）——本综述按 §6.2 hedge：这是 intervention 准确率而非 Pearson correlation，慎用作 "LME 调度损失 15 % 减排" 的反推。
    4. CMEF (cascading marginal emissions factor): B5 (Nat. Commun. cascading-EV, 作者待 verify) 在 EV 大规模充电场景下指出当多个 large flexible load 联动时单点 MEF 不再 price-taker；提出 group-staggered 信号。本综述按 §6.4 hedge：EV → DC 迁移在学术界未验证，明确写"机制迁移待验证"而非引为既成事实。

    6.1.1 Pigouvian 信号设计的经典假设与 carbon-aware DC 的不匹配#

    经典 Pigouvian 税理论假设：(a) 个体行为对外部性的 marginal cost 已知；(b) 个体是 price-taker；(c) marginal cost 信号在 ex post 可验证。在 carbon-aware DC 调度上，这三个假设都有不同程度不成立：

    • (a) marginal cost 已知: carbon signal (MCI / LME) 是对真实 marginal emission 的估计；信号提供商之间差异（§7.4）使 marginal cost 本身有不确定性。
    • (b) price-taker: §6.2 / §6.6 / §6.7 反复强调当 hyperscaler 占 grid 比重上升后该假设崩溃。
    • (c) ex post 验证: §6.9 第三阶层（结果层）actionability 指出只有 LME 类信号有较强经验证据。

    这三个不匹配使得"用 carbon signal 引导调度"在严格意义上需要 cascading-aware 修正、ex post audit、以及 mechanism design 三层都升级——本综述 T2 概念骨架的核心论点。

    6.2 Price-Taker 假设何时崩溃#

    Banerjee (1992) herding 与 Pigouvian 信号在 carbon-aware DC 调度上的衔接关键是 price-taker 假设。当 hyperscaler 规模相对 grid balancing footprint 小时，MCI 信号可视为外生；当占比上升（如 PJM 2035 load forecast 中 data center 占比据 M7 引用的 PJM 报告达到 94 %、ELCC 77 %、总量 210 GW——本综述按 §6.2 hedge：数字源自 PJM 2025 load forecast 报告，引用须注 forecast vintage），price-taker 假设崩溃，信号需变为 cascading-aware。

    T2 (cascading-aware Pigouvian + Banerjee herding) 是本综述穿越 Thread B 的核心概念骨架；§10.2 把它与 Thread C 的 capacity-market 失效对接。

    6.3 Operational vs Embodied Carbon: 单 Knob 优化结论翻转#

    B8 Carbon Explorer (传 Acun et al. Meta, 作者待 verify) 显示，当 embodied carbon 计入后，许多 operational-only 优化的结论会翻转——本综述按 §6.4 hedge：引用 B1 / B2 / B7 时须复述 embodied 假设。

    6.4 Critique 与 Actionable Scope-2#

    B3 (Wiesner & Kao, Moving Beyond Marginal Carbon Intensity, arXiv:2507.11377) 对 MCI 同时作为 carbon accounting 与 grid flexibility 度量提出系统 critique：在缺 LME 与 cascading 修正的 MCI 信号下，许多"减排"实际是会计层面 reshuffling 而非物理减排。本综述把 B3 与 B5 视作两条并行 critique 线（B3 靶 MCI 的度量充分性，B5 靶 price-taker 假设崩溃），并在 §11 Open #2 中合并为 "hyperscaler-scale cascading carbon 稳定性" 这一统一问题。

    6.5 Signal-Baseline Normalization 的方法学需求#

    B1 / B2 / B6 / B7 / B9 各用 WattTime / ElectricityMaps / EPA eGRID / 自建 nodal 信号，导致 "能省 X %" 文献间数字 mosaic 误导（§6.4 fact-check）。本综述在 §7 spatial-temporal 章节做信号-baseline normalization 小节填补 Seam B-4 (CMEF baseline drift)。

    6.6 Banerjee Herding 在 Carbon Signal 上的具体 instantiation#

    Banerjee (1992) 的信息瀑布 / herding 模型指出，当多个个体在公开信号下顺序决策时，后续个体会忽略私有信号、跟随前者，导致信息聚合失效。把这一模型套用到 carbon-aware DC 调度：

    • 公开信号 = MCI / AEF；
    • 个体决策 = hyperscaler \(n\) 决定是否把 workload shift 到信号低碳 region；
    • 失效场景 = 所有 hyperscaler 同时根据 MCI 信号 shift，导致 "低碳 region" 在 ex post 实际边际机组上升、信号自我证伪。

    这一失效与传统 Pigouvian 信号设计的核心假设 (price-taker) 直接冲突。B3 (该论文 arXiv:2507.11377 作者待 verify) 的 critique 在概念层面已经触及，但未给出形式化；B5 (Nat. Commun. cascading-EV 作者待 verify) 在 EV 上给出 cascading marginal emissions factor (CMEF) 的 group-staggered 修正。把 CMEF 迁移到 hyperscaler-scale DC fleet 的研究尚未公开发表——这是 §11 Open #2 的具体 framing。

    6.6.1 Why Not Otherwise：LME vs CMEF 不是二选一而是分层叠加#

    读者可能合理追问：既然 LME 已经把 signal 下沉到 nodal 粒度、cascading 失效又主要由 fleet 规模诱发，是否可以"只用 LME、忽略 CMEF"？反方观点同样合理：CMEF 在结构上已经修正 cascading，是否"只用 CMEF、降级 LME"？本综述的立场是两者层叠不替代，理由如下：

    • LME 解决 spatial 信号粒度问题，CMEF 解决 group-level 反馈失效问题——二者攻击的失效模式不同（前者是 region-level mis-attribution，后者是 herding feedback），不能相互替代。
    • CMEF 的 stagger schedule \(\Delta(g, t)\) 必须在某种 base signal 上修正——若 base 取 region MCI 而非 nodal LME，cascading 修正仍然继承 region-level 粒度损失。
    • 降级到只用 CMEF 意味着放弃 LME 的 nodal 价值发现：B4 实证 LME-guided intervention 的 accuracy ≥ 85 % (按 §6.2 hedge) 是相对 nodal baseline 的，不在 region 信号上等价复现。
    • 降级到只用 LME 意味着继承 price-taker 假设：在 PJM 2035 forecast 中 data center 占比 94 % 的极端场景（按 §6.2 hedge: forecast vintage）下，LME 自身会被 hyperscaler 群体行为反向 corrupt——nodal 越精细，群体同步反馈失效得越快。

    因此 §10.4 中的 stitch 把 LME 作为 base signal、CMEF 作为 group-level 修正层，分层叠加而非 either-or——这与 §10.6 commit-audit-penalty 博弈中"envelope 物理上界 + commitment 制度上界"的分层结构同构。

    6.6.2 Cascading Carbon 加重 vs 减轻 Herd 的 Boundary#

    §6.6 把 Banerjee herding 套用到 carbon-aware shifting，得到 "all hyperscalers see same signal → simultaneous shift → signal self-falsifies" 的失效叙事，但这一叙事不是普遍真理，而是条件命题。本综述识别三个 boundary 变量：

    • fleet 规模 \(N\)（同时观察 signal 的 hyperscaler 数）： \(N\) 小时单次 shift 对 ex post 边际机组影响小、herding 不实质失效；\(N\) 大时累计影响显著。
    • signal 自相关结构 \(\rho\)： 当 \(\rho\) 高（信号在 hyperscaler 决策窗口内持续指向同一 region），shift 集中落在同一 bus → cascading 加重；\(\rho\) 低时 shift 自然 self-averaging。
    • 决策同步度 \(\tau\)： 所有 hyperscaler 共用同一 signal provider（如统一 WattTime API）且决策窗口对齐时 \(\tau \to 1\)，cascading 最严重；异步决策（不同 signal vintage / 不同更新频率）使 \(\tau\) 远小于 1，cascading 缓解。

    cascading 加重的实际触发区域大致是 \((N \cdot \rho \cdot \tau)\) 三者乘积超过某阈值。这一阈值在公开文献中尚未实证，是 Open #2 的具体 quantitative 子目标。反向 corollary： 在 fleet 小、signal vintage 异质、决策异步的早期阶段，cascading 风险被高估；在 PJM 2035 forecast 假设（94 % data center 占比）成立后，三个变量同时高，cascading 风险变为 dominant——这也解释了为何监管层（FERC M1）选择此时（12/2025）介入而非更早。

    6.7 Mechanism Design 候选：Group-Staggered CMEF#

    B5 给出的 group-staggered 信号 示意结构 (illustrative) 为：

    \[\mathbf{c}_t^{\text{CMEF}}[g, n] = \mathbf{c}_t^{\text{MCI}}[\text{region}(n)] + \Delta(g, t),\]

    其中 \(g\) 是 staggered group 编号、\(\Delta(g, t)\) 是 stagger schedule 引入的修正项。实际形式可能是 cohort-window-piecewise 或 capacity-share-weighted 而非纯可加（如 \(c^{\text{CMEF}}[g,t,n] = c^{\text{MCI}}_t[\text{region}(n)] \cdot \mathbb{1}(t \in W_g) + \dots\)）；B5 原文公式形式 待 verify。直观含义是把同一时刻接收 shift 指令的 fleet 拆成多 cohort、错开响应窗口（类比 traffic light 错峰），从而避免群体性 cascading。

    把这一 mechanism 应用到 hyperscaler-scale DC fleet 时需要解决两个问题：

    1. stagger schedule 与 SLO 的耦合： \(\Delta(g, t)\) 必须不破坏 latency-critical inference 的 SLO；这一约束与 §3.5 的异质性观察连通。
    2. CMEF 的 audit 可行性： 跨 RTO / 跨 utility 的 CMEF audit 度量尚未标准化——这与 Open #3 (统一 audit metric) 直接合流。

    6.8 与 Thread C M11 ORDC 失真的结构性同构#

    Thread C M11 (Aurora 商业咨询 报告作者待 verify) 在 ERCOT 侧报告：当 large flexible load 占 grid 比重上升后，ORDC scarcity 价格信号被这些 load 主导后失真——直观上是同一 cascading 现象在 capacity / scarcity 市场上的 instantiation。

    这一观察使得 (B5 CMEF cascading) 与 (M11 ORDC 失真) 在 mechanism-design 失败 taxonomy 中同源。本综述把二者并列处理 (§10.3) 是综述差异化的核心结构性贡献之一。

    6.9 信号设计的 actionability 三阶层#

    把 §6.1–§6.8 内容整合，可以把 carbon signal 的 actionability 划分为三个阶层：

    1. 第一阶（信息层）： signal 是否可观测、是否有透明 source、是否包含足够的 nodal / temporal 分辨率。当前 AEF / MCI / LME / CMEF 在这一阶层差异明显——AEF 最透明但分辨率最低，LME 最高分辨率但 source 较新（B4, Cote & Sun, arXiv:2512.18819）；CMEF 还在概念阶段（B5, EV 上 instantiate）。
    2. 第二阶（决策层）： signal 能否被 scheduler 实时纳入 control loop。这一阶层受 §4.10 滞后约束与 §5 sub-second 物理边界影响。当 signal 更新频率与 control loop 不匹配，actionability 在工程层崩溃。
    3. 第三阶（结果层）： signal-driven 决策的物理减排是否能 ex post 验证。B3（critique）与 B4（LME 与真实削减 ≥85 % 相关性，按 §6.2 hedge）在这一阶层做对照——只有 LME 类 signal 在第三阶层有较强经验证据。

    本综述的信号设计 framing 是：在第一阶层选择最高分辨率（LME / nodal）+ 在第二阶层匹配 control loop（envelope-based dual-timescale, §10.2）+ 在第三阶层做 cascading 修正（CMEF）。这一组合在公开文献中尚无 single paper 完整实现。

    7.5 Spatial-Temporal Shifting 的 Schedulability 约束#

    Thread B 主流文献把 workload 当作同质 batch；但 Thread A §3 已经指出 training 的 \(\alpha'_j\) 二阶约束。把 B 与 A 缝合的形式化在 §10.1 给出：spatial shifting 决策必须以 \(\alpha'_j\) 为可行域约束。

    7.5.1 Spatial Shifting 与 Network Routing 的耦合#

    spatial shifting 决策不仅影响 power 与 carbon，也影响 network routing 与 inter-DC bandwidth 利用：

    • training 跨 region shift 需要传输 model checkpoint + dataset，带宽消耗大；
    • inference 跨 region shift 主要影响请求 routing，对带宽影响小但对延迟敏感。

    网络 fabric 的能耗在 hyperscaler 总能耗中占比通常被忽视，但实际可达 5-10 %。spatial shifting 若忽略 network 能耗，可能在跨 region 移动中实际增加总能耗——这是 §6.4 actionable scope-2 critique 的一个 corollary，但尚未在 carbon-aware shifting 文献中显式建模。

    7.6 跨 Continent 数据传输成本与 Shifting 的物理边界#

    spatial shifting 在直觉上是把 workload 移到低碳 region，但实践中存在跨 continent 数据传输成本的物理边界：

    • training: model checkpoint 与 dataset 体积巨大；跨 continent 传输的网络成本与时延通常使 training spatial shifting 退化为 "checkpoint 后 region 内重启"——这与 §3.2 checkpoint scaling law 直接耦合。
    • inference: 模型权重已经预部署，inference shifting 只需 routing 决策，跨 continent shifting 的边际成本主要在 latency（这与 §3.5 latency-critical 类的 \(\alpha \approx 0\) 冲突）。
    • batch inference / fine-tuning: 中间值，主要受 data locality 与 SLO 影响。

    这一物理边界使得 B2 / B7 等给出的 spatial shifting 上限数字 (5–35 %) 在实际生产部署中可能被进一步压缩；引用时须复述这一边界条件。

    7.6.1 Data Locality Constraint 与 Carbon-Aware Shifting 的张力#

    许多 inference 与 fine-tuning 工作负载受到 data locality 约束：数据存储在特定 region 的合规需求（GDPR、各国数据本地化法律）或 latency 需求使得 workload 不能跨 region 自由 shift。这一约束对 carbon-aware spatial shifting 上限的影响在文献中通常被低估：

    • 欧洲 GDPR 与各国数据本地化：限制 user data 离开特定 jurisdiction；
    • 中国数据出境合规：限制企业用户数据离开中国；
    • 金融 / 医疗等高合规行业：要求数据不离开特定数据中心；
    • inference latency 敏感场景：必须在用户接近 region。

    这些约束使得 spatial shifting 的实际可达范围远小于 §7.1 给出的"5–35 %"工程上限。本综述提示：carbon-aware shifting 的"理论上限"与"合规可达上限"是两个不同概念，文献多关注前者而 industry 多受后者主导。

    7.7 与 Thread C Co-location 的冲突#

    24/7 CFE (B1, B7) 与 co-location BTM (M3 Talen-Amazon) 在 mechanism design 上存在概念冲突：

    • 24/7 CFE 假设 workload 可以跨 region 自由 shift，以匹配 hourly CFE 供给；
    • co-location BTM 把 DC 与 specific generator 物理绑定，shift 能力被绑死在 single site。

    这一冲突在 FERC M1 EL25-49-000 (12/2025) 的 Firm CDS / Non-Firm CDS 区分中得到一种制度回应：Firm CDS 隐含放弃 grid-interactive 灵活性以换取交付确定性；Non-Firm CDS 保留灵活性但承担 curtailment risk。Firm CDS 接近于传统大工业电力交易；Non-Firm CDS 接近于真正意义的 GIFL（grid-interactive flexible load）。在 EL25-49-000 docket 中两类 CDS 的定义、计量、违约条款细节尚待 compliance filing 确定（compliance window 收口于 2026-02-16/17，PJM 实际于 2/17 提交，详见 §9.1）。本综述把这一观察作为 §10.4 LME-LMP 对偶分析的支撑论据。

    7.8 Carbon Signal Provider 之间的方法学差异#

    §7.4 normalization table 已经按列对照 signal provider，本节从方法学层面进一步说明四种主流 signal provider 的差异：

    • WattTime: 以 marginal emissions 为核心，分钟级粒度，覆盖北美主要 grid；其 signal 在过去几年被广泛用作 carbon-aware shifting 的事实标准。
    • ElectricityMaps: 以小时级 MCI / AEF 为主，覆盖全球；与 WattTime 在 marginal 定义上略有不同，跨平台数字不可直接对照。
    • EPA eGRID: 年度 emission factor，主要用于 reporting 而非 dispatch。
    • 自建 nodal: 学术工作（B4 LME, Cote & Sun）或大型 hyperscaler 内部，分辨率最高但 source 不公开。

    这一方法学差异使得 "1 % flex → X €/MWh" 这类边际数字（如 B7 该论文报告的 1.29 €/MWh）在跨 signal provider 比较时几乎不可比——这也是 §11 Open #3 (统一 audit metric) 在 signal 侧的具体 framing。

    7.9 Spatial Shifting 的政治经济边界#

    spatial shifting 在制度上还受到州际 / 国际能源政策的边界约束：

    • 州 RPS (renewable portfolio standard) 差异：把 workload 从加州 (高 RPS) shift 到亚利桑那 (RPS 较低) 在 carbon 上可能减排（夏季太阳能丰富），但在 RPS 合规上可能制造 strategic loophole。
    • 跨境贸易：欧洲 ENTSO-E 内部跨国 shifting 是 mature 的；北美跨 RTO 仍受 transmission constraint 限制；亚洲跨国互联尚未常态化。
    • co-location 与 RPS 计入：M3 Talen-Amazon BTM case 在 PJM 的 RPS 计入上有争议（不在本综述详述范围，引用待 case 法律 brief）。

    这些政治经济边界使得 spatial shifting 的"可实现上限"远低于 §7.1 给出的物理-工程上限。

    §8 Water-Power-Carbon Tri-Nexus & LCA-Dispatch Bridge (Thread B / T5 主)#

    8.1 Water 维度的引入#

    近期 LLM 训练 / 推理的 water footprint 引起广泛关注。B10 SLIT (arXiv:2505.23554, 作者待 verify) 在 4-objective Pareto 上联合优化 (carbon, water, cost, TTFT)；B11 (Patterns, 作者待 verify) 给出 annual LCA 视角下的 carbon 与 water 总量估算。据 B11 该论文报告，AI workload 增长下的 carbon 区间为 32.6–79.7 Mt，water 区间为 312.5–764.6 GL——本综述按 §6.2 hedge：区间宽源于 AI workload 增长假设差异，不要 cherry-pick 上界。

    8.2 Wet-Bulb-Driven Hourly Water Intensity (T5 桥接信号)#

    WUE (water usage effectiveness) 通常以 annual 静态值给出；但 cooling 系统的 effective water consumption 在 hourly 尺度上由 wet-bulb temperature 主导。本综述提出候选信号 \(\mu_t^{\text{wb}}\) (T5 桥接)：

    \[\mu_t^{\text{wb}} = g\big(T_{\text{wb}}(t, \text{site}), \text{cooling tech}\big).\]

    该信号在已 verified 文献中尚未被显式 instantiate；将其作为 §11 Open #4 的子部分之一。

    8.3 4+ Objective Pareto 的空白#

    B10 SLIT 给 4-objective Pareto，但 spatial-scale 在 single site / small fleet；B11 / B12 给 annual LCA 但无 hourly dispatch；B4 给 nodal LME 但无 water。Sunbelt (water-stressed) / PNW (low carbon, low cost) / Nordic (low carbon, high cost) 这三类典型 site 的对偶选择在 3+ objective Pareto 上尚无公开文献联合实证 ——这是 Open #4 的具体 framing。

    8.4 LCA-Dispatch Bridge#

    annual LCA (B11 / B12) 与 hourly dispatch (B1–B9) 之间存在一个时间尺度桥接 gap：

    • LCA 给 long-run 嵌入碳与水量，影响 site / hardware 选型；
    • dispatch 给 short-run 节碳 / 节水边际；
    • 二者耦合在文献中通常以 amortization 处理 (B8 Carbon Explorer 是早期尝试)。

    本综述把 LCA-dispatch bridge 列为 §10.7 三方 stitch 的支撑信号设计；在 §11 Open #4 中要求未来工作把 \(\mu_t^{\text{wb}}\) 与 amortized embodied LCA 在 Pareto front 上联合处理。

    8.5 Sunbelt / PNW / Nordic 三类典型 site 的对偶选择#

    把 §8 的三联 nexus 投影到典型地理选址上，可以看到一个 trilemma：

    • Sunbelt (亚利桑那 / 德州内陆 / 加州 Central Valley): 太阳能廉价（低 LMP / 低 MCI 部分时段），但 wet-bulb 温度高、水资源紧张 (高 \(\mu_t^{\text{wb}}\))。是 Phoenix demo (A1) 与 ERCOT 75 MW 规则 (M5) 的主战场。
    • PNW (太平洋西北): 水电主导（低 MCI，电力低成本），但极端干旱年水电出力下降（与 water 维度耦合）。是 Google / Meta 历史 fleet 的核心。
    • Nordic (北欧): 低碳排（核电 + 水电 + 风电），气候冷使 cooling water 需求低，但电力成本中高、地理与主要 inference 用户距离远（latency 不利）。

    三类 site 的对偶选择天然形成 3+ objective Pareto 问题，但 B4 (nodal LME) / B10 (4-obj SLIT) / B11 (annual LCA) 三篇分别覆盖 (LMP+LME / cost+carbon+water+TTFT / carbon+water annual) 中的不同子集——没有任何一篇把三类 site 的 hourly nodal LME × hourly \(\mu_t^{\text{wb}}\) × annual amortized embodied LCA 联合分析。这是 Open #4 的差异化承重 framing。

    8.5.1 三类典型 Site 的具体气候 / 电网约束#

    把 §8.5 三类典型 site 与具体气候 / 电网约束细化：

    • Sunbelt: Phoenix / Tucson 平均干球温度高、湿球温度中、冬季温和；ERCOT 与 WECC 边界覆盖；夏季太阳能丰富但晚高峰 net load (duck curve) 严峻；M5 ERCOT 75 MW 规则直接适用。water 维度 dominant，wet-bulb 在 evaporative cooling 下 sensitivity 高。
    • PNW: Oregon / Washington 全年温和湿润、水电主导 (BPA 区域)；冬季 storms 偶发供电紧张；夏季干旱年水电出力下降、carbon 上升。M1 PJM EL25-49-000 不直接适用，但 BPA 与 WECC 各自 mechanism。water 维度受水电与 cooling 双重影响。
    • Nordic: Sweden / Finland / Norway 寒冷气候使 cooling 几乎免费；核电 + 水电 + 风电组合提供低碳电力；电力市场是 Nord Pool 跨国市场；与北美 RTO 框架不直接可比但有概念互通性。

    三类 site 的对偶选择在工程实践中往往不是单一最优，而是 hyperscaler 把 fleet 分散在三类之间以做 portfolio hedging。本综述对这一 portfolio 视角持开放态度，并把它列为 future research agenda 的潜在框架。

    8.6 Water 维度对 FERC Mechanism 的间接影响#

    water-stressed region 的 inference latency-critical workload 是否可以被纳入 ERCOT critical load exception (M5) 范畴，是综述最难的概念整合点之一（详见 §10.7 三方 stitch）。直观上，inference latency-critical 类不属于传统 "critical infrastructure"，但当水资源紧张到影响公共健康时，inference 服务的中断也可能传导到关键基础设施（如医疗 inference / 应急 chatbot）。这一边界判定在 FERC / PUCT 框架下尚无明确判例，是 future regulatory research agenda 的一部分。

    8.7 Embodied Carbon 与 Hardware Refresh Cycle 的相互作用#

    GPU 硬件 refresh cycle 通常在 3-5 年；新一代 GPU 的能效提升与 embodied carbon 之间存在一个 break-even 计算。该论文 (B8 Carbon Explorer, 传 Acun et al. Meta 作者待 verify) 在其 LCA 模型中已经处理这一权衡，结论是单一 operational knob 优化往往忽视 embodied 翻转。在 AI 行业 GPU 短缺的当下，"使用更多旧 GPU vs 加购新 GPU" 的选择对 embodied carbon 与 grid-side 投资压力都有传导效应——这一选择的 mechanism design 框架尚未在文献中显式建立。

    8.8 Water 与 Cooling Technology 的耦合#

    不同 cooling 技术（air-cooled vs evaporative vs immersion vs direct liquid）对 water 与 power 的相对消耗显著不同：

    • air-cooled: WUE 低但 PUE 高；
    • evaporative (蒸发冷却): WUE 高（尤其在干燥地区）但 PUE 低；
    • immersion / direct liquid: WUE 与 PUE 都低，但 capex 高。

    \(\mu_t^{\text{wb}}\) 信号（§8.2）在 evaporative cooling 下 sensitivity 最高、在 air-cooled 下几乎为零。这一异质性使得 water-aware shifting 的有效性高度依赖 fleet 的 cooling 技术构成——B10 SLIT (arXiv:2505.23554) 在 4-objective Pareto 中已经隐含处理这一异质性，但显式 mapping 仍是 future work。

    8.9 LCA 与实时 dispatch 的 amortization 桥接#

    B11 (Patterns 作者待 verify) 与 B12 GCOS (作者待 verify) 给出 annual LCA 视角；B1–B9 给出 hourly dispatch 视角。把二者 amortize 到同一时间尺度的工程做法通常是：

    \[\text{Effective hourly carbon}_t = \mathbf{c}_t^{\text{operational}} + \frac{\text{Embodied LCA}}{\text{hardware lifetime hours}}.\]

    这一公式看似简单，但其有效性依赖三个假设：(a) hardware lifetime 在不同 utilization 下不变（实际并非如此，高利用率会缩短寿命）；(b) embodied LCA 不随生产年份 / 地点变化（实际取决于上游电网清洁度）；(c) 不同 hardware 代际的 embodied 可线性 amortize（实际新一代 GPU 的 embodied 显著高于上一代）。

    把这三个假设的 fragility 纳入综述讨论是 Open #4 (tri-nexus Pareto) 的支撑——若不显式 amortization 桥接的 fragility，三联 Pareto 的"减排"声明在 ex post 验证中可能被推翻。

    8.9.1 Embodied Carbon 的供应链上游不确定性#

    embodied carbon 的最大不确定性来源是供应链上游：GPU 制造（TSMC 等代工厂）、HBM（SK Hynix 等存储厂）、机房建筑（混凝土与钢材）等环节的 carbon footprint 都依赖各自所在区域电网清洁度与生产工艺。当 GPU 短缺导致全球范围内代工产能向东亚集中（电网清洁度较低）时，新一代 GPU 的 embodied carbon 可能逆向上升——这与 GPU 能效提升的趋势相反。

    把这一上游不确定性纳入 LCA 分析，B11 (Patterns 作者待 verify) 的区间 32.6–79.7 Mt 实际可能 underestimate。本综述按 §6.2 不做点估计，但提示读者：LCA 不是单点数字，而是带不确定性区间的随机变量——这一框架性观点是 §11 Open #4 的概念前提。

    9.1.1 Why Not Otherwise：Firm vs Non-Firm CDS 的 real-option 边界#

    EL25-49-000 把大型 flexible load 拆为 Firm CDS（确定性交付、放弃 GIFL 灵活度）与 Non-Firm CDS（保留灵活度但承担 curtailment risk）。读者可能合理追问：在 risk-averse hyperscaler 视角下，为什么 Firm CDS 不直接 dominant？两者并列是否只是 tariff 形式上的多样性？本综述的回答是：这是经典 real-option 选择 (Dixit-Pindyck 框架)，dominant 策略取决于 carbon / scarcity 信号 volatility 与 hyperscaler 的边际成本结构：

    • 当 carbon / scarcity signal volatility 低、hyperscaler 业务模式以 latency-critical inference 为主（§3.5 \(\alpha \approx 0\)），Firm CDS dominant——放弃低价值灵活度换取交付确定性。
    • 当 signal volatility 高、hyperscaler 业务模式以 training / batch inference 为主（高 \(\alpha\)，高 \(\alpha'\) 可在 burst window 内 shift），Non-Firm CDS dominant——保留灵活度的 option value 超过 curtailment 风险。
    • 这一 boundary 也解释了 §7.7 提到的 24/7 CFE × co-location 概念冲突：24/7 CFE 隐含选择 Non-Firm 一侧（高灵活度）、co-location BTM 隐含选择 Firm 一侧（绑定单一 generator）；二者不是冲突而是 portfolio 的两端。

    real-option 形式化（与 §10.6 commitment game IC 条件叠加）尚未在公开文献完成；本综述把它作为 Open #3 (统一 audit metric) 的子部分——audit metric 必须能在两个 option 上同时定义才能跨 RTO 比较。

    9.11 Williamson Hold-Up 与 Commitment-Audit-Penalty Game#

    把 Thread C 各 RTO mechanism 投影到 Williamson (1979) hold-up + 实时系统 schedulability 的联合框架，可以看到一个统一结构：

    • commit 期 (\(t = 0\)): hyperscaler 与 RTO / utility 在 queue 期签订承诺，确定 envelope 与 curtailment 承诺量 \(\Delta P^{\text{commit}}\)、CDS 类型、capacity baseline 等；
    • audit 期 (\(t > 0\)): RTO 在 metering 数据上 audit hyperscaler 的实际 curtailment \(\Delta P^{\text{actual}}_t\)；当 \(\Delta P^{\text{actual}}_t < \Delta P^{\text{commit}}\)（兑现不到位，under-delivery）或 \(p^{\text{actual}}_t > \bar p^{\text{env}}\)（envelope 上界违约）触发 \(V^{\text{penalty}}\)；
    • hold-up 风险: 若一方在 commit 后做特定投资（hyperscaler 的 site 选址 / RTO 的 transmission 建设），另一方可能在 audit 期 strategically renegotiate——这是 Williamson 经典 hold-up 在 grid-load 关系上的 instantiation。

    本综述把 T3 (commitment-audit-penalty + Williamson hold-up) 作为 Thread C 的概念骨架，并在 §10.6 用 IC 条件给 defer ↔ shift mechanism 等价性的判定准则。

    9.12 Capacity Market vs Energy Market 的 Audit 度量差异#

    PJM NCBL (M7) 是 capacity market 的 baseline 概念，与 ERCOT 75 MW (M5) 的 interconnection 阈值、SPP 90-day (M6) 的 provisional service 在度量上根本不同：

    • capacity baseline (NCBL): 在容量充裕度评估中以"未参与 DR 时的 baseline 负荷"作为 capacity 贡献度量；NCBL 的争议在于 large flexible load 的 baseline 本身就具有 strategic 灵活性。
    • interconnection threshold (75 MW): 是 ex ante gating 度量，不涉及 ex post audit；但 critical load exception 的判定是 ex post discretionary。
    • provisional service (90-day): 介于 capacity 与 energy 之间，给 RTO 一个短期 commitment window，类似于 option 合约。

    跨 RTO 比较三类度量在同一 hyperscaler 资产上的 audit 结果，将揭示 mechanism choice 对 hyperscaler 行为的隐性激励——这一比较研究尚无公开文献完成。

    9.12.1 Ancillary Service 与 Capacity 的双向收益#

    除 capacity baseline 与 interconnection 阈值外，AI DC 还可在 ancillary service 市场（regulation up/down, spinning reserve, FFR）参与。A12 (Ren, Sun, Wang, Harrison, arXiv:2510.01050) 在 RTO 侧建模 DC 作为 FFR provider 的系统价值；A2 (Choukse et al., Microsoft Azure team) 给出 facility 侧 sub-second 响应能力。但 ancillary service 的资格认证（如 PJM Reg-D / ERCOT FFR）在当前框架下并未明确包含 DC 类资产——这是 §11 Open #1 的 regulatory 子部分。

    一个具体的开放问题是：若 DC 同时持有 capacity (M7 NCBL) 与 ancillary service (假设资格被纳入) 两类合约，二者之间的相互对冲 / 相互冲突如何在 audit 期被监管？现有 RTO 框架默认 capacity 与 ancillary 资产相互独立（不同发电机），但 DC 是单一资产同时提供两类服务，激励兼容性问题待研究。

    9.12.2 Co-location 与 Grid-Connected 边界的政治经济学#

    M3 Talen-Amazon Susquehanna ISA case 把 co-location 与 grid-connected 的边界争议推到了 FERC 决策层面。该案的核心问题是：当 hyperscaler 与 generator 物理 co-locate 时，是否还需要按 grid-connected 模式承担 transmission cost、capacity payment、与 ratepayer 之间的成本分摊？

    直观上 co-location 减少了 transmission 负荷，似乎应享受 cost relief；但反方观点（AEP / Exelon 抗议书报告 $140 M/年 cost shift，按 §6.2 hedge 非中立数字）认为 co-location 实际上把原本由 hyperscaler 承担的 grid-connected fixed cost 转嫁给其他 ratepayer——形成 cross-subsidy 风险。

    FERC 在 2024-11 以 2-1 投票拒绝 Talen-Amazon ISA（按 §6.3 hedge：commissioner 立场需核 docket 原文）。这一拒绝在 12/2025 EL25-49-000 中升级为对全部 co-location 安排的 tariff 区分需求。本综述把这条决策路径视为 mechanism design 在 federal 层面 evolved 的代表性案例。

    9.12.3 Capacity Market 中 AI DC 的 ELCC 不确定性#

    PJM ELCC（effective load carrying capability）方法学传统上为发电机（特别是 intermittent renewables）设计，但近年开始扩展到 large flexible load。AI DC 的 ELCC 评估面临几个不确定性：

    • 历史 baseline 缺乏: AI DC 是新兴 load 类型，没有像传统工业负荷那样的历史 baseline 可参照；
    • 业务模式 evolve 速度快: 训练 / 推理 mix 随产品演化快速变化，ELCC 假设的稳定性差；
    • 跨年比较困难: 同一 hyperscaler 在不同 capacity delivery year (DY) 上的 ELCC 可能显著漂移。

    PJM 2025 forecast 报告中给的 ELCC 77 % 数字（按 §6.2 hedge：forecast vintage）反映的是当前评估方法下的 best-guess，未来随方法学迭代可能显著调整。这一不确定性对 hyperscaler 投资决策、对 RTO capacity adequacy 评估都有传导效应。

    9.13 FERC Federal vs RTO State 层级冲突#

    FERC EL25-49-000 (M1) 与 PUCT 75 MW 规则 (M5) 在司法层级上分别属于 federal 与 state；DOE Secretary Letter → FERC ANOPR RM26-4 (M2) 也是 federal 层。当 hyperscaler 在跨 RTO 部署时，必须同时满足 federal tariff + state interconnection + RTO operating procedure 三层约束。该论文 (M4 Chen & Zheng, arXiv:2604.05376) 在 framing 中已经触及这一多层制度复杂性，但未给具体跨层 IC 分析——这是 Open #3 (统一 audit metric) 的政治经济学子部分。

    10.1 A ↔ B Stitch (1)：Schedulability-Aware Carbon-Shifting#

    Thread B 主流文献（B1 / B2 / B7 / B8 / B9）把 workload 视为同质 batch；Thread A §3 已指出 training \(\alpha'_j\) 二阶约束 (NCCL collective hypergraph)。把二者缝合的形式化：

    • inner-loop (sec–min): 跟 grid frequency / 价格信号 (\(\Delta f_t, \boldsymbol{\lambda}_t, \sigma_t\))；
    • outer-loop (hour–day): 跟 carbon / water 信号 (\(\mathbf{c}_t, \boldsymbol{\mu}_t\), \(\mathbf{c}_t^{\text{LME}}, \mathbf{c}_t^{\text{CMEF}}, \mu_t^{\text{wb}}\))；
    • 两个 loop 用 envelope \((\bar p, \underline p)\) 解耦。

    inner-loop 在 envelope 内部"快"调；outer-loop 在 envelope 时间序列上"慢"塑形。这一框架与 M9 audit envelope 四元组 (§10.5) 直接对接。

    10.6 A ↔ C Stitch (2)：Defer ↔ Shift 的 Mechanism 等价性#

    A14 = M4 (Chen & Zheng, arXiv:2604.05376) 给 defer vs shift framing；Thread C Seam C-4 提出问题：FERC RM26-4 下若 defer commitment 可被运行期 shift 部分替代，IC 是否被破坏？本综述把这一问题正式化为 commitment game。设 hyperscaler 在 queue 期承诺削减量 \(\Delta P^{\text{commit}}\)（即峰时段相对 baseline 可削减的功率），运行期实际削减 \(\Delta P^{\text{actual}}_t\)；envelope 兑现不到位（under-delivery）触发罚金：

    • 承诺 \(\Delta P^{\text{commit}}\)（curtailment commitment）；
    • 运行期 audit \(\Delta P^{\text{actual}}_t\)；
    • 惩罚 \(V^{\text{penalty}} = \max\big(0, \Delta P^{\text{commit}} - \Delta P^{\text{actual}}_t\big) \cdot \lambda_t\)（即"承诺削峰未到位"部分按 \(\lambda_t\) 计罚；envelope-上界违约 \(\max(0, p^{\text{actual}}-\bar p^{\text{env}})\) 是另一方向，本节聚焦 under-delivery）。

    IC 条件（玩具数值示例）: 设 hyperscaler 接入许可价值 \(V^{\text{commit}} = \$10\) M/年；audit 命中并强制兑现概率 \(\Pr[\text{shift 替代成功}] = 0.5\)；违约罚 \(V^{\text{penalty}} = \$3\) M；shift 替代 defer 的 expected savings 记为 \(V^{\text{audit}}\)（即 shift 相对 defer 多节省的值）。当 \(V^{\text{commit}} - V^{\text{audit}} \cdot \Pr[\text{shift 替代成功}] \le V^{\text{penalty}}\)，即 \(10 - 0.5 V^{\text{audit}} \le 3 \Leftrightarrow V^{\text{audit}} \ge 14\) 时，shift 比 defer 划算，IC 被破坏——hyperscaler 会战略性选择 shift 而非真正 commit。

    这一形式化是本综述的核心理论贡献候选——把 Williamson hold-up 与 real-time-systems schedulability 在同一 mechanism design 空间内对照。

    10.6.1 Commitment Game 的扩展：多 Hyperscaler 联合 Audit#

    §10.6 的 commitment game 是 single hyperscaler vs single RTO 的双方博弈；但实际市场中存在多个 hyperscaler 在同一 RTO 内同时签订 commitment 的情形。把博弈扩展到多 hyperscaler 联合 audit 时，会引入以下新问题：

    1. 协同 strategic withholding: 多个 hyperscaler 是否会在同一时间段 strategically 同时 underperform commitment（类似 oligopolistic 行为）？若 RTO penalty 总量有限或 enforcement 资源稀缺，这一行为可能 sustainable。
    2. 信息透明度: 各 hyperscaler 的 commitment 与 actual performance 是否对其他 hyperscaler 公开？若公开，会强化 herding（§6.6）；若不公开，会增加 RTO audit 复杂度。
    3. Stackelberg 优先级: large hyperscaler 与 small hyperscaler 在 commitment 谈判中的议价能力差异；large hyperscaler 可能享受 RTO 默认的"too big to penalize"地位。

    这些扩展问题是 mechanism design 的 frontier，与 §10.3 cascading 失效在结构上同源。本综述把它们作为 future formalization 的 anchor。

    10.7.1 三方 Stitch 的具体形式化挑战#

    §10.7 三方 stitch 是综述最难的概念整合点。把其形式化为可解 optimization 问题面临以下挑战：

    1. 时间尺度跨越巨大： schedulability 在 sec-min、signal 在 hourly、commitment 在 queue-year，跨 6+ 个数量级。
    2. 变量耦合非线性： 例如 \(\alpha'_j\) (NCCL 拓扑) 与 \(\mathbf{W}_t\) (workload-site 分配) 是 hypergraph × matrix 的非线性耦合。
    3. 不确定性多源： carbon signal 随时间随机、water signal 随天气随机、commitment penalty 受 ex post discretionary 影响。
    4. 多 agent 博弈： hyperscaler 之间存在 strategic interaction，不能简化为 single-agent optimization。

    针对这些挑战，可能的研究路径包括：

    • 分层 model predictive control (MPC) + 多时间尺度滚动优化；
    • 多 agent reinforcement learning + game-theoretic constraint (Nash / Stackelberg)；
    • chance-constrained / robust optimization 处理 multi-source uncertainty；
    • 引入 mechanism design 中 strategy-proof 设计（VCG / IC-IR）作为外层约束。

    本综述不在 v1 阶段闭合这一形式化，但把它列为综述最强的理论 framing 候选——若未来工作能给出一个 reduced-form prototype，将显著推动 §11 五个 Open Problem 的整体解决。

    10.9.1 Stitch 形式化的实证支撑路径#

    把 §10.1–§10.7 七个 stitch 形式化为可验证命题，需要不同程度的实证支撑：

    • §10.1 schedulability-aware shifting: 需要 open testbed 上 training 与 inference workload 共调度的实证；A1 Phoenix 给单一类型实证，需要多类型 mix 扩展。
    • §10.2 dual-timescale envelope: 需要 sub-second 与 hourly 两个尺度信号同时驱动同一 cluster 的实证；目前未公开。
    • §10.3 cascading 同源: 需要 ERCOT 实际 ORDC 数据与 hyperscaler fleet 行为数据的联合分析；hyperscaler 数据通常 inaccessible。
    • §10.4 LME-LMP 对偶: B4 (Cote & Sun, arXiv:2512.18819) 给 LME 实证、PJM ISO 给 LMP 实证，二者数据可联合获取，是相对可行的实证路径。
    • §10.5 Phoenix = M9 envelope: A1 已给 envelope 实测，需要在多 RTO 上 replicate 才能验证 audit 可行性。
    • §10.6 defer ↔ shift IC: 需要建模 + 多 hyperscaler 联合实验，难度最高。
    • §10.7 三方 stitch: 难度最高，目前更适合作为 framing 而非实证目标。

    这一可行性排序使得 §10.4 与 §10.5 是最适合 v1 综述发表后立即跟进的实证 follow-up；§10.6 与 §10.7 是长期理论 frontier。

    10.9.2 Cross-Domain 对比：V2G / HVAC DR / AI DC 三类 Flexible Load 的同与异#

    把 AI DC 作为 grid-interactive flexible load 放在已有 flexible load 经济学的 family 中，可立刻看到三类资源在 mechanism design 关键维度上的同与异。这一比较是 mid-tier 综述差异化的最强 lever——若 AI DC 与 V2G / HVAC DR 的差异只是规模，则现有 DR 机制 retrofit 即可；若差异是结构性的，则 mechanism 设计必须重做。

    维度 EV V2G HVAC DR AI DC (GIFL)
    典型规模 kW per asset, MW per fleet 10s kW per building, MW per aggregator 10s–100s MW per site
    响应时间尺度 sec–min（充电桩 firmware） min–hr（thermal inertia） µs–hr（multi-scale, §5.8 nested envelope）
    可中断性 \(\alpha\) 本质 binary + state-of-charge dep. 连续（thermal comfort band） heterogeneous（training \(\alpha'\) 二阶 / inference \(\alpha \approx 0\) / batch \(\alpha\) 高，§3.1）
    决策周期 vs 信号粒度 信号 hourly、决策 min（基本匹配） 信号 hourly、决策 hr（匹配） 信号 hourly、决策 ms–min（严重失配, §6.0 / §10.2）
    price-taker 假设 通常成立（单车辆小） 成立到 aggregator 层 崩溃（hyperscaler-scale, §6.6.2）
    mechanism 现状 TOU + V2G pilot（早期） DR program 成熟、capacity baseline 长期实践 FERC 刚起步（EL25-49 12/2025）

    commitment 期限 per-session（无 multi-year） seasonal DR program queue–year（M3 ISA / M5 75 MW gating）
    cascading 风险触发 充电同步 peak（已 partial 实证） weather-driven 群体同步（已实证） signal-driven 同步 shift（B5 EV 上 instantiate，DC 未验证，§6.6）

    结构性观察： AI DC 在四个维度上与 V2G / HVAC DR 结构性不同：(a) sub-second 物理边界 vs 后两者的 sec+ 边界；(b) workload 异质性使 \(\alpha\) 不是单一标量；(c) 信号-决策时间粒度严重失配；(d) commitment 期限跨 queue–year 而非 per-session 或 seasonal。这四点合起来意味着 V2G / HVAC DR 的现有 mechanism (TOU / DR baseline / capacity bidding) 不能直接 retrofit——FERC EL25-49-000 创设新 tariff (Firm/Non-Firm CDS) 而非套用现有 DR 框架，正是对这一结构性差异的制度回应。

    这一 cross-domain 对照也回填了 §1.3 "本综述差异化定位" 的一个隐含论点：AI DC 不是 V2G / HVAC DR 的"放大版"，而是 mechanism design 空间中的新 instantiation——这一论点本身值得在 future work 中单独 formalize。

    §11 Open Problems, Risks & Future Agenda#

    11.0 Boundary Conditions：claim 何时反转#

    本综述若干承重 claim 不是普遍真理而是条件命题。本节显式列出三处最重要的 boundary，作为读者评估 claim 适用范围的 quick reference：

    11.0.1 Phoenix −25 %×3 h envelope 的失效区域。 A1 (Colangelo et al., Nature Energy 2025/26 online) 报告的 envelope 实测来自 256-GPU training-dense cluster + 干燥气候 + 单一 demand response call 触发条件。可识别的至少三种失效边界：

    • (a) Inference-dense cluster： 当 cluster 是 inference-dense 而非 training-dense，envelope 上下界 ratio 应 widen（A3 21 % > 3 % oversubscription 异质性，§4.1）但 sustain 时长缩短（inference latency tail 不容长时压缩）——envelope 形状改变，不能直接套 "−25 % × 3 h"。
    • (b) 高湿球温度时段 + evaporative cooling： 当 cooling 是 evaporative（§8.8）且 wet-bulb 高时段，深度功率压缩触发 thermal-electrical 双约束——envelope 在 Sunbelt 夏季 wet-bulb 高峰时可能 collapse 到 ratio < 1.15。
    • (c) Collective-heavy training phase： 当 training job 处于 all-reduce 集中段（§3.3.1 NCCL 通信高峰），sub-second swing 把 nominal envelope 中线本身上下拉扯，"−25 %"的 baseline 变得不稳定——这是 §5.8 nested envelope 必须被引入的具体理由。

    这三种失效区域共同说明：A1 Phoenix 数字是单点实参化而非通用上限，引用时必须复述 cluster mix / cooling tech / training phase 三个 qualifier。

    11.0.2 Cascading carbon 的反向 herd boundary。 §6.6.2 已展开三变量 \((N, \rho, \tau)\) 阈值；此处补一条结构性 corollary：在阈值以下（fleet 小、signal vintage 异质、决策异步）阶段，cascading-aware mechanism 反而可能 over-engineer——过早引入 CMEF stagger 会损失 LME 的 nodal 价值发现而无对应收益。这意味着 mechanism design 的时间表本身具有 phase-shift 性质：2026–2028 LME-dominant、2028+ CMEF-dominant 是一种可能的演化曲线，而非二者同时上线。

    11.0.3 Sub-second envelope 友好 vs 威胁的 boundary。 §5.10 指出 GPU sub-second swing 在没有 envelope 时是 grid 威胁、在有 envelope + mechanism 时是 grid 资源——但 boundary 实际位置是 (inverter share × grid inertia × ROCOF threshold) 的联合区域。在低 inverter share 高 inertia 的传统 grid（如 PJM 当前），sub-second swing 即便不显式被 audit 也大致 grid-friendly；在高 inverter share 低 inertia 的未来 grid（如 ERCOT 高 renewables 时段），同一 swing 不被 audit 即变为系统稳定性威胁。Open #1 的 deliverable 必须 quantify 这一联合区域，否则"sub-second envelope" 听起来像普遍解，实际只在某些 grid state 上 binding。

    11.1.7 Unsolved vs Unaddressed：Empirical-Closable vs Fundamental Ill-Posed#

    五个 Open Problem 在性质上并不同源：有些是 unaddressed（empirical 数据不足、可在 open testbed 上闭合），有些是 unsolved（mechanism design / formalization 层面 ill-posed，需理论突破）。这一区分对学术 ROI 评估直接关键——前者 1–2 年 dataset 投入可见显著 deliverable，后者 5+ 年理论工作才能给出 reduced-form prototype。

    Open # 类别 闭合路径 主要障碍
    #1 sub-second envelope unaddressed (empirical-closable) open testbed 上 ms 级 envelope characterization + multi-cluster replication hyperscaler 数据不可获取 + metering 标准 (§5.9)
    #5 training preemption scaling law unaddressed (empirical-closable) open training cluster 上 \(R(N, G, C)\) 实证 GPU 与训练规模成本（学术界算力不足）
    #2 cascading carbon 稳定性 unsolved (fundamental) mechanism design (CMEF 形式化) + agent-based 模拟 + 多 hyperscaler 联合 audit price-taker 假设崩溃下 IC 设计是开放数学问题
    #3 跨 RTO 统一 audit metric unsolved (fundamental) mechanism design (envelope 四元组形式化) + federal vs state 制度协调 RTO 历史路径依赖 + 政治经济约束（不可纯学术解）
    #4 water-power-carbon 三联 Pareto unsolved (fundamental) multi-objective optimization + signal 设计（\(\mu_t^{\text{wb}}\)）+ LCA-dispatch bridge 多源不确定性 + 长短期尺度协调

    学术 ROI corollary： Open #1 / #5 是基础层（§11.4.5 已述）且 empirical-closable，优先级最高；Open #2 / #3 / #4 是 fundamental ill-posed，更适合作为 5–10 年 theoretical agenda。本综述识别 #1 / #5 为 "empirical-closable" 同时也意味着它们的解可以独立于 mechanism design 进展先行——不必等 FERC ANOPR final action 即可启动。

    警告： 这一二分类不是绝对边界——例如 Open #1 包含 metering 标准升级的 regulatory 子部分（§5.9），后者更接近 unsolved；Open #4 的 wet-bulb signal 构造（§8.2）是 empirical 部分，混合性质。本综述把分类作为 ROI quick-guide，而非论断每个 problem 的本体性质。
